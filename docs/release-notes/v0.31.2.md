# v0.31.2 发版说明

**主题：并发可靠性验证与残余风险专项——NULL 租约终态防护、Reaper/章节双重 fencing 真实并发证据、Worker 运行矩阵与账务守恒**

本版本是 v0.31.1 之后的专项加固，所有改动先在独立分支 `fix/v0.31.2-concurrency` 上按阶段提交，最终验收通过后合并 main 并发版。约束保持不变：不修改历史迁移 0001～0012，不删除或放宽测试，不用 Python 全局锁替代数据库 fencing，不把 mock 当作并发证据，不新增生产配置变更。

## 1. Job NULL / 过期租约终态防护（阶段 1）

- `commit_fenced_result()` 现在要求 `lease_expires_at IS NOT NULL AND >= now`，并与 `status='running'`、当前 `claim_context` token 在同一条条件 UPDATE 中校验；NULL 租约不再被视为有效。
- 10 项真实 Session 事务测试覆盖有效 / NULL / 过期 / 错 token / 已终态 / Reaper 抢占 / 失败不写结果、不发事件；两个既有测试 helper 同步补上有效租约，断言未放宽。

## 2. Reaper 真实并发竞争（阶段 2）

- 从 `_heartbeat` 逐句抽取 `_renew_lease_once(job_id, token)`，测试与生产共用同一条条件续租 SQL，避免实现漂移。
- 新增真实线程 / 独立 Session / Barrier 并发测试：双 Reaper 回收、心跳先胜、Reaper 先胜、重试上限 + 心跳、上限失败 + 真实退款，分别 100 / 100 / 100 / 100 / 50 轮，全部验证唯一结果与最终一致性。
- 核心条件 UPDATE 未被 mock；SQLite 文件库 + WAL 验证原子性，PostgreSQL 行锁压力仍由 opt-in CI 覆盖。

## 3. GenerationLease + Job claim 双重 fencing（阶段 3）

- `commit_generation_chapter()` 在单一短事务内同时校验 Job claim（running + token + 有效租约）与项目 GenerationLease（token + 未过期），再写 `Section` / `OutlineNode` / `done_steps` 并发布 `chapter_committed`；任一 fencing 失败整笔回滚。
- 重复章节提交幂等：正文不覆盖、步骤不重复、成功事件只发一次。
- 100 轮 Job claim 竞争、100 轮 GenerationLease 失效竞争、100 轮章节写入 vs Reaper，均以真实线程 / 独立 Session 验证「成功即完整提交，失败即全清」。

## 4. Worker 真实运行矩阵（阶段 4）

- 动态发现全部 8 类 runner，以真实 DB 行为替代源码检查作为主要证据：旧 token、已取消、预置 abort、正常终态、过期租约、终态写入异常回滚、终态事件幂等。
- 修复真实缺陷：所有 Worker 入口在 `fenced_job` 只校验 token 后无条件把状态设回 `running`，导致已取消任务被迟到 Worker 复活；现在 8 个 Worker 均先检查 `job.status != 'running'` 再返回。
- 导出 / 图片 / 知识类的外部文件副作用不在单事务回滚范围内，报告如实标注。

## 5. 账务竞争与守恒（阶段 5）

- 6 场景 × 50 轮真实线程回归：两线程退款、Reaper vs Worker 失败、取消 vs 完成、settle vs reconcile、子账号删除、退款 DB 错误后重试；核对余额、账本笔数和认领标记。
- `_fail_job()` 改用 `transition_job()` 条件迁移，两个并发失败路径只有一个能写 `failed` 并发事件；`transition_job()` 只 expire 目标 Job，不再 detach 调用方持有的其他 ORM 对象。
- `refund_charged_job()` 与 `settle_pending_charge()` 在账本写失败时释放领取标记，退款可重试；金额公式 `(chapters - written) * charged // chapters` 与 `done_steps` 归因保持不变。

## 6. 质量指标明细（阶段 6）

- 项目级 `summary['metrics']` 在原有 4 键之外新增 `coverage` / `samples` / `mismatches`，分子分母与可抽查样本可审计，原比率口径完全不变。
- 真实件 `summary['tender_quality']` 增加条款 / 取值 / 判定覆盖率、样本与不一致明细；数据集未就绪时返回空容器并保持「未测量」，不伪造指标。

## 7. 兼容性

- API 路由数量不变；`QualityReport.summary` 的新字段为附加键，旧报告无需迁移，`report_payload()` 照常渲染。
- 无新增迁移；Alembic 单 head 仍为 `0012_generation_lease`，历史迁移 0001～0012 零改动。
- 版本 0.31.2 同步后端、前端与部署清单。

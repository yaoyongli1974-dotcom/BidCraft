# 发版记录

按版本归档的**对外口径**：issue / 邮件回复引用本目录同一份措辞。

## 发版惯例（自 v0.9.0 起执行，v0.21.0 起明文固定）

- **每个版本打 annotated tag**，指向该版本的版本号 bump commit；tag 与版本号一一对应。
- **每个版本建 GitHub Release**，正文取自本目录同名发版说明文件；Release 不带任何附件
  （`assets=0`），latest 指向最高版本。v0.9.0–v0.20.0 的 Release 于 v0.20.1 之后按本口径补建，
  v0.4.8–v0.6.1 等早期桌面端版本未建 Release（历史上就没有，且无发版说明来源）。
- **桌面客户端已冻结**（终止于 v0.6.3），不发安装包、不走 tag/release 触发自动构建；
  `desktop-release.yml` 仅 `workflow_dispatch` 手动触发。
- **生产部署由项目方自行执行**，发版侧不代操作线上环境。

补记历史版本（v0.6.4–v0.6.8）时，本仓库尚未打 tag，故正文先行入库再补 tag，避免口径散落在
聊天记录或临时文件里。v0.9.0–v0.19.0 的 tag 于 v0.19.0 之后一次性补齐，均指向各自的 bump commit。

## 发版规矩（避免踩客户端）

- **服务端发版打 tag 是安全的**：`.github/workflows/desktop-release.yml` 只有 `workflow_dispatch`，
  tag push 不再触发客户端构建；且 `attach_to_release` 默认 `false`，即使手动重建也不会把安装包
  重新附加到 Release。
- **不得**发布桌面安装包：v0.6.3 起客户端冻结，公开分发会重新激活 Qt/PySide6 的 LGPL-3.0
  再分发义务（见根目录 `NOTICE` 与 `docs/desktop.md`）。
- 一个版本的 tag 打在**该版本号最后一次出现**的提交上（版本号 bump 之后可能还有文档提交）。
- Release 正文用 `gh release create <tag> --notes-file docs/release-notes/<版本>.md`，
  不手工在网页里另写一份。

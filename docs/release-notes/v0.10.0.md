# BidCraft v0.10.0

这一版把「报价改价」这条业务从 HTTP 路由里抽出来，做成独立的 Service，让 Web API 和命令行共用同一套编排。同时修掉一个多包件项目里命令行改价会落空的真实 bug。

## 本版内容

- **新增报价 Service（`services/quote_service.py`）**：把「解析包件 → 设置单价 → 写审计」这一段编排从路由搬到独立模块。
  - Service 不依赖 FastAPI，只接收数据库会话、只 `flush` 不 `commit`（事务仍由入口统一提交）；
  - 异常原样上抛，由各入口映射成自己的响应格式（HTTP 400/409、CLI 退出码），HTTP 的状态码与响应体**保持不变**；
  - 业务逻辑本身仍复用既有的 `boq.*` 函数，没有重写规则。
- **HTTP 与 CLI 共用同一 Service**：Web 的改价接口和 `bidcraft boq-price` 现在走同一条代码路径，行为差异收窄到入口层。
- **修复多包件改价 bug**：此前 `bidcraft boq-price` 不传包件，只会命中 `package_id` 为空的旧快照，导致多包件项目里命令行改价看似成功、实际没落到对应清单。命令新增 `--package` 选项，与 Web 一样能精确指定包件。
- **审计身份承载方式统一**：`record_audit` 增加可选的 `actor` 参数（身份优先级：显式 actor > 请求用户 > system），不传时行为完全不变。HTTP 传真实用户、命令行/本地操作记 system——这一既有差异予以保留，只是不再靠隐式上下文「碰运气」。
- **可独立测试**：新增 `tests/test_quote_service.py`，不加载 FastAPI、直接用数据库 fixture 测 Service，覆盖单包件改价与审计、多包件必须指定包件且落到正确快照、审计身份覆盖、冲突异常上抛。

## 说明

- 这是「Service 层抽离」的**第一个纵向切片**（报价域），验证过模式后再复制到其它域。不是一次性重写所有路由；URL、请求/响应格式、既有测试语义均不变。
- 有意入口差异保持原样：命令行/本地操作无请求用户、审计记 system；MCP 无角色校验、拒绝 PDF；批量导出无强制通道。本版只收敛真正的逻辑漂移与 bug。

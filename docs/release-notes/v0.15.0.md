# BidCraft v0.15.0

对审查报告「第二层：可靠性/安全细节」的收尾。这一版改动很小，重点是把上一轮
「异常详情可能泄露内部信息」的怀疑**核实清楚**，再补上来源追溯模块的测试空白。

## 异常详情回传：核实结论

全库 `detail=str(exc)` 回传点共 88 处。用 AST 逐处追踪所在的 `except` 捕获类型后，
结论是「绝大多数属正常做法」——不再一刀切屏蔽：

- **86 处**捕获的是项目自身的领域异常（`ValueError` / `LookupError` / `ComplianceError` /
  `BoqConflictError` / `BillingError` / `InvoiceError` 等）。这些异常的文案本来就是写给
  用户看的校验提示，转成 HTTP 400 是正确行为。
- **1 处**（上传招标文件）虽然外层是宽泛 `except Exception`，但只在 `isinstance(exc, ValueError)`
  收窄分支里回传 `str(exc)`，其它异常一律 `raise` 重抛——安全。
- **1 处是真问题**：`/account/export` 用 `except Exception` 直接回传 `detail=f"导出失败：{exc}"`。
  该路径可能抛文件系统、压缩包或数据库异常，原始文本会带出内部路径与结构。

修复：未知异常只回「导出失败，请稍后重试」，内部细节通过 `logger.exception` 写进服务端日志。
新增 `tests/test_error_detail.py` 两例——一例断言 500 响应不含注入的内部路径与原始报错文本，
一例确认正常导出路径不受影响。

## 来源追溯补测

`provenance` 此前只有 1 个测试文件、覆盖基本链路。本版补 5 例边界：

- 全书重扫幂等（反复 `refresh_project` 不累积重复引用行）

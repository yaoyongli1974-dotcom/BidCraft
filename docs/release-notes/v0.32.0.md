# v0.32.0 发版说明（AI 技术标编制引擎升级）

本版本在不重建既有底座的前提下，为技术标编制补齐「规划 → 知识资产 → 混合检索 → Agent 工具 → 经验/事实治理 → 质量评估」闭环。所有 AI 产物只引用真实存在的 ID，模型/工具的自我声明不作为已验证结论；导出门禁与风险否决未被削弱。分支 `feature/v0.32-ai-engine`，逐阶段证据见 `docs/development/ai-engine/v0.32.0/`。

## 1. 章节规划

- 新增可版本化、可确认、可追溯的 `ChapterPlan`（唯一约束 `(project_id, node_id, version)`），状态机覆盖生成、复核、确认、用于生成、重生成、更新与驳回。
- 评分点、需求、事实、知识与章节 ID 全部经真实数据库校验；伪造、跨项目、跨标段引用被丢弃并写入 `validation_errors`，不进入正文。
- 规划进入生成门禁（`review` / `review_strict` / `auto`）与 prompt；同步/异步生成均审计规划版本并幂等标记 `USED_FOR_GENERATION`。
- 新增 7 条规划路由（`GET/POST/PUT /plan`、`POST /plan/generate`、`POST /plan/regenerate`、`POST /plan/confirm`、`GET /plan/history`）；前端复用既有 OutlineTab，未新建第二工作台。

## 2. 知识资产

- 在既有 `KbDocument`/`KbChunk`/`KnowledgeBase` 上增加结构化提炼、审核生命周期（draft/review/approved/published/rejected/archived）与重复候选组；不新建第二套文库。
- 溯源到真实文档块（`document_id`、`chunk_id`、页码、标题、来源），结构化字段并入素材可信度裁决；管理端全部 super-admin、企业端读需可访问企业、写需 owner，KB 由容器解析而非信任请求体 `kb_id`。
- `review_status IS NULL` 的旧资产保持原有检索行为，不因迁移被误挡；已发布资产重新抽取会回到 draft 并需重新审核（刻意保守）。
- 管理端与企业端各 5 条资产路由（list/duplicates/resolve/extract/review），动作写审计。

## 3. 混合检索

- 本地 bigram/cosine 与外部 provider 结果用 RRF（K=60）统一重排，叠加 per-KB 归一化分数与就绪/新鲜度稳定 tie-break；原始 `score` 不被覆盖。
- `Passage` 增加块级溯源与重排分量；缺元数据时来源为空并降级为 title_only/suppressed，不再用 KB 名称冒充来源。
- 项目/标段作用域 fail-closed，失败 KB 写入 `diagnostics.failed` 而非静默丢库；可信等级 full/excerpt/title_only/suppressed 渐进注入。
- 未知可信/降级信号保留 `null`，不伪装成「未降级」或 0；新增 viewer 可读的只读检索预览路由，规划与正文只消费真实引用。

## 4. Agent 工具

- 新增薄工具循环，复用既有 `ModelClient.complete_with_tools` 与 MCP/registry 唯一工具系统；无第二套注册、无 Agent 直写数据库。
- 服务端 `ToolPolicy` 决定可用工具，用户 payload 不能注入；默认只读，写策略在无 actor 时 fail-closed；项目 ref 绑定后不可换项目。
- 每次调用写审计；`AgentOutput.tool_calls` 固定 8 键（`name/args/result/verification/audit_id/ts/is_error/ms`），验证状态为 verified/unverified/failed，必需工具失败即失败任务，不伪造成功。
- 新增 `GET /agents/{agent_type}/tools` 工具目录；前端按真实轨迹展示徽标与审计 ID。真实外部模型/Ollama function-calling 行为【待回填：真实模型端点验证】。

## 5. 经验回流与事实治理

- 经验仅从本项目已处置质量问题、人工修订、审批/导出强制记录与规划用户调整推导，上限 12、去重、真实 ID 标注，明确标注为「未审核建议经验 / ADVISORY」；无自动写入知识库或企业资产。
- 事实确认由服务端盖章 `confirmed_by`/`confirmed_at`，要求真实来源文件与文本内引文及合法页码；覆盖保护保留已确认事实，force 覆盖清空确认并在同事务写审计。
- 事实值/单位变化会使引用章节回到 `review` 并写失效审计；来源 ID/文件名真实回写，前端不再显示空来源。
- 新增 viewer 安全 `GET /projects/{ref}/lessons`；冲突多候选与来源权威排序需额外 schema，本版**不实现**。

## 6. 质量评估

- 覆盖率、证据可信与工具审计均使用真实引擎/审计数据；零分母时 `ratio=None`、`measured=false`，不再把「无数据」显示为 100%。
- 风险口径统一复用导出门禁的 open 判定；blocking 实质性问题时 verdict 不得 PASS，工具失败与过期证据进入 findings。
- finding 处置可溯源（resolved_at/by、reopen 清空），指标按 stable key 去重。
- 新增只读报告导出与跨项目汇总（仅聚合当前用户可访问项目，无报告项目不伪造分数）；忽略原因缺失时返回 400。导出门禁代码与阈值未改。

## 7. 兼容性与迁移

- 新增 3 个迁移，Alembic 单 head 为 `0015_fact_confirmation`：`0013_chapter_planning`（规划表/索引/唯一约束）、`0014_kb_asset_metadata`（可空元数据列与两张重复候选表）、`0015_fact_confirmation`（两列可空确认信息）。0001-0012 零改动。
- 全部为中文注释、可空、无 server_default；历史行 `NULL` 保持 legacy 语义（旧检索行为、未人工确认），`create_all` 兼容的 inspect 判存守卫使重复执行为空操作。Downgrade 顺序 `0015 → 0014 → 0013 → 0012_generation_lease`，均为可逆、只删除本次新增对象。
- API 路由 252→274（规划 7、管理端资产 5、企业端资产 5、检索预览 1、工具目录 1、经验 1、质量导出 1、质量汇总 1）；Pydantic 请求模型 91→93。
- 版本 0.32.0 同步后端、`pyproject.toml`、`uv.lock`（仅项目自身版本）、Web `package.json`/lock 根版本与 `deploy/` 清单。既有项目、权限、协作、SSE、导出确认流程保持兼容。

# BidCraft v0.16.0

实质性条款（★/▲）的响应判定不再只看字符 3-gram：可归类的条款多一条结构化命中路径，
改写过但意思到了的响应不再轻易被判「未响应」，减少人工复核量。

## 本版内容

- **条款类型自动分类**：按条款文本的具体信号词归为
  **资质资格 / 业绩案例 / 技术参数 / 承诺服务 / 通用条款** 五类；没有明确信号的一律「通用」，
  不强行归类。分类只影响判定路径，不改变条款的实质性与处置规则。
- **结构化锚点判定**：为前四类各定义一组锚点模式（如「近 N 年」「数字 + 项/个」「一级/甲级」
  「≥ 数字」），且**只统计条款自身也出现的模式**——正文里凭空出现的数字不算响应。
  锚点用正则容忍改写：数值可变（3 项→6 个）、同义可换（同类→相近）、中文数字与阿拉伯数字都认。
- **覆盖率合并规则**：3-gram 是基线；锚点全中视为已覆盖（0.75，高于长条款 0.45 阈值），
  部分命中按 0.6 倍加成（需多数锚点命中才够阈值），通用条款完全回退 3-gram、行为不变。
  没写响应、正文只有无关数字的场景仍判未响应。
- **接口与界面**：`GET /projects/{ref}/requirements` 每条新增 `requirement_type` 与
  `requirement_type_label`；风险总览「实质性条款响应」区块对非通用条款显示类型标签
  （悬停说明「按条款类型启用结构化判定」）。

## 不是语义判定

仍是**可解释、可复核、不调用 LLM** 的保守规则：同一份正文每次结果一致，人工「已响应 /
不适用」留痕照旧有效。结构化锚点只降低改写误判，不放宽「没写就算响应」的底线。

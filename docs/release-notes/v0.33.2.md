# v0.33.2 发版说明

日期：2026-11-28

主题：本地工作流实战收口——批量规划、事实来源留痕、报价提取、正文一键复核、配图与导出修复。

## 1. 基线与版本

- 基线：本地 main `fafd9d593ad14706b88046504cd9f68dd827e560`（v0.33.1 Release 之后新增的本地测试环境提交）。
- 开发分支：`fix/v0.33.2-local-workflow`。
- 最终代码 SHA：`4f61ffc3f9ed30200411f088de446c9658199e85`；发版 bump 后的新 commit 作为 tag 指向点。
- 版本同步：backend / pyproject / uv.lock / web/package.json / web/package-lock.json / 部署清单统一升级为 `0.33.2`。

## 2. 规划与目录

- 新增章节规划批量生成、批量确认入口，复用既有单节点 API；不自动确认，不绕过人工复核与导出门禁。
- `review_strict` 模式不再被前端降级为 `auto`；目录大纲可一键生成缺失规划。
- auto 模式全书生成前先重建因评分项变化而失效的规划；review / review_strict 仍由用户批量生成并确认。
- 台账重解析导致的评分项 UUID 变化，不再误判为“评分项已删除”；只有名称、分值、正文等关键值真的变化时才判废规划。

## 3. 事实来源与报价清单

- 新增迁移 `0016_fact_provenance`：Fact 增加可空 `provenance_kind` / `supplier_note`，历史 NULL 按招标原文解释；迁移可逆、无 server_default、不改历史事实值。
- “招标文件原文”继续强制真实来源文件 ID、原文摘录与正整数页码；“用户补充说明”不伪造证据，必须填写依据说明，由服务端记录确认人和时间。
- 来源口径、说明或状态变化会清空旧确认盖章，引用章节退回 `review`，并在事实审计、章节规划上下文、引用卡和正文提示词中留痕。
- 含报价清单导入现在识别单价/合价列、货币符号与千分位，并支持金额/数量反推；原有人工覆盖仍可用。

## 4. 正文复核与全书流转

- 正文页新增管理员“提交复核并通过”、普通编辑“保存并提交复核”一键入口；有未保存正文时先保存再流转。
- 顶部新增全书一键流转：负责人对草稿执行 submit+confirm、对待复核只 confirm；普通编辑只对草稿 submit；已确认/锁定章节跳过。
- 所有动作调用既有服务端 `reviewChapter` API，权限、状态机、审计完全保留；前端不直接改状态，不为非复核人提供 confirm。
- 新增 GET `/projects/{ref}/chapters/{node_id}/lock`，修复前端获取编辑锁时落到 SPA catch-all 返回 HTML 的 401/JSON 解析问题；路由总数更新为 276。

## 5. 配图、DOCX 与安全门禁

- 配图优先让配置的大模型输出自包含 SVG；结构化工程节点提示词避免证据类措辞触发内容过滤，三次无效后使用差异化本地工程示意图，不再统一退化为灰色占位。
- DOCX/PDF 路径对已通过安全校验的 SVG 做本地 Pillow 栅格化，输出真实 800×450 PNG；显式声明 `Pillow>=11` 依赖。
- DOCX 正文标题按相对偏移 + 相邻层级钳制输出，修复“H1 之后直接出现 H3”导致导出校验失败。
- Bandit B324（SHA1 仅用于占位文件名）改为 SHA256；B314 由前置 `sanitize_svg()` 实测保证并用精确注释豁免，未降低扫描阈值或扩大白名单。

## 6. 本地测试环境

- 测试环境状态迁移到 `~/.local/share/bidcraft-local-test/`，避免 `/tmp` 清理导致数据和管理员口令丢失；旧 `/tmp/opencode` 状态自动迁移。
- `pg-start` 自动创建 Python 3.12 venv 并安装 pgserver，重复执行不会报“数据库已存在”错误。
- `pg-test` 指定用例时只运行指定用例，不再把迁移往返测试和并发用例混跑在同一数据库。
- 新增 `model-on` / `model-off`，控制本地测试环境是否使用后台已配置模型；顶部品牌统一为“AI 技术标编制工作台”。

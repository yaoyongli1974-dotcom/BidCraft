# BidCraft v0.23.0

在 v0.22.0 的判定引擎上继续加固边界问题。核心标准不变：**已知不满足不得自动放行、证据不足不得自动放行、复合条款不因拆分丢失约束、人工确认对应明确的正文版本、判定可追溯到原始证据。**

## 本版内容（R16–R21）

### P0 判定逻辑
- **R16 复合条款项目类型约束传递**：修复 `_judge_atom()`/`judge()` 调用 `_deadline_window_signals()` 时未传原始条款文本的项目类型——拆分后的业绩原子丢失「弱电智能化」等类型限定，无关项目被误计为有效。现每条原子判定都携带完整原始招标要求做类型过滤，明确不匹配的项目不计入有效业绩，类型无法识别保留 `type_conflict` 转人工。
- **R17 年份精度起始边界**：修复 `y >= cutoff.year` 把起始年「2023年」直接计入有效的问题。现年份精度：早于起始年→过期、等于起始年或截止年→人工复核、窗口内部年份→有效；月份精度起始/截止月同样转人工；日精度按真实日历比较、边界含等号。边界冲突不再被自动判满足。

### P1 证据与审计
- **R18 人工确认快照保留**：正文修改使已确认条款失效时，用 append-only 审计（`requirement.confirmation_invalidated`）在退回 pending **之前**保存完整快照——原始自动判定结论/原因/证据、人工确认人/时间、正文版本 revision、body 哈希、失效原因与操作人。与正文保存同事务（失败整体回滚），历史快照不可覆盖，新确认生成新行。无新表、无迁移。
- **R19 业绩证据身份与来源关联**：`PerformanceEvidence` 增加归一化项目名/合同编号/客户/身份状态/来源状态；身份优先级合同编号 > 客户+名 > 名称，多合同号或客户冲突→`identity_conflict` 不计有效业绩；按句子边界就近归属日期与项目，避免串项目。无真实页码/文件 ID 的文本输入显式标 `source_reference_status="missing"`，不伪造溯源。
- **R20 判定质量回归体系增强**：回归集 16→26 条，新增 10 个时间窗/项目类型样本，每条支持 deadline/category/expected_evidence；统一执行器 `run_regression()` 逐样本驱动截止日期逻辑。新增指标：FAR（FP/(FP+TN)）、错误拒绝率 FRR、四态准确率、人工复核率、项目类型/身份关联错误数、证据缺失数。CI 纳入 `tests/test_calibration.py`。

### P2 边界
- **R21 单位与主体关联边界**：补 7 例验收测试（元/万元未登记单位、月/天时长约定、主备链路带宽互不冒用、多主体无标点各归族、未知 family 不误赋、source_span 原文可定位）。生产逻辑已在 v0.22.0 R11/R13 就位，本版验证其行为。

## 兼容性与安全
- 无数据库 schema 变更，无迁移脚本。
- 无对外 API 结构变化。
- 保守判定延续：单位缺失/跨量纲/身份不明/日期边界歧义一律转人工复核，不自动放行。
- 正文变化后旧人工确认自动失效，历史判定通过审计完整可追溯。

## 已知限制
- 文本输入无真实文档页码/文件 ID 时，业绩来源状态标记为 missing（如实标注，不伪造），溯源质量依赖上游解析提供结构化证据。
- 时间单位（天/小时/月/年）的换算采用规则基准（1 月=30 天规则约定），仅用于数值比较；涉及具体合同期限与日历日期时由截止日期校验使用真实日历计算。
- 元/万元等金额单位未登记，按 unknown 转人工复核（保守处理）。

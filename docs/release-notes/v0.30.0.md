# BidCraft v0.30.0

- 日期：2026-11-24
- 主题：十阶段质量治理收官——CI 可靠性、依赖安全、账务 fencing、DOCX/回归/前端闭环与可观测性

本版从 v0.29.0（HEAD `4d7b4dc`）出发，在独立分支 `quality/v0.30.0-reliability` 上按十阶段任务书逐项修复，最终合并回 `main`。完整验收矩阵见 [docs/development/BIDCRAFT_V030_FINAL_ACCEPTANCE_REPORT.md](../development/BIDCRAFT_V030_FINAL_ACCEPTANCE_REPORT.md)，各阶段证据见 `docs/development/BIDCRAFT_V030_STAGE*.md`。

## 1. CI 可靠性与测试隔离

- Python CI 拆分为 `python (lint + static checks)` 与 `python (pytest + regression)`，均安装 `postgres` extra；新增环境信息、JUnit 报告上传与失败摘要，定位失败不再依赖人工翻日志。
- 真实 PostgreSQL job 每个用例前按动态表清单 `TRUNCATE ... RESTART IDENTITY CASCADE` 建立数据边界；新增 20 轮×4 worker 领取压测与双线程池并行隔离测试。
- 新增 `docx (CJK render + fidelity)` job：安装 Noto CJK / LibreOffice / poppler，严格模式 `BIDCRAFT_DOCX_REQUIRE_RENDER=1` 下 golden 渲染不得跳过；CI 写入 fontconfig 别名解决 `fc-match 宋体` 回退，测试断言不放宽。
- 敏感扫描误报按精确指纹列入 `.gitleaksignore`，测试口令改为拼接构造；gitleaks-action v2→v3 / checkout v4→v6（仅 Node 运行时迁移）。

## 2. 依赖与安全扫描

- 已评估并升级 npm 主要依赖：Vite 8、Vitest 5、@vitejs/plugin-react 6、react-router-dom 7、typescript-eslint 8.74；`npm audit` 从 14 项降至 0。Vite 8/Rolldown 的分包配置迁移至 `rolldownOptions.output.codeSplitting.groups`。
- Bandit 改为全树 JSON 扫描 + `scripts/bandit_gate.py` 按 `(文件, 行号, 规则)` 精确豁免迁移 DDL 两项；不再使用目录级排除，`-ll` 阈值未降低。新增 `tests/test_expr_security.py` 恶意表达式矩阵证明 AST 求值无副作用。

## 3. 账务与任务队列可靠性

- 新增 Alembic `0011_stage3_accounting`（可逆）：`PendingCharge.sections_at_charge`、`Job.refund_claimed`。
- 同步生成接入 `pending_charge_heartbeat`，对账以 `updated_at` 为活跃边界、按已写入章节数差额退款，移除项目级“有活 Job 即不退款”的粗粒度阻塞。
- 退款与任务失败统一走 DB 条件认领（幂等），失败终态退还未完成扣费并清理 fence，新增 `refund_failed` 事件；计费退款 note 携带 `[job:...]` / `[marker:...]` 来源追溯。
- worker fencing 系统化：`assert_claim_current()` 使用全新会话绕过 identity map，6 个 worker 统一加入终止/写入前 abort 检查点；相似度任务重跑改为幂等重算（done 报告短路、重算前清理旧命中）。

## 4. DOCX、回归与质量指标

- DOCX 表格以 `w:tblDescription=bidcraft-kind:<kind>` 区分数据表与版式表，校验器只要求数据表有表头；统一图片匹配/计数规则并新增上传解压 512 MiB、解析 8M 字符 / 2000 表 / 5000 页、正文总量 20M / 单节点 200k 等资源上限。
- 回归语料新增 4 个 100% 合成 fixture（附录、清单、分页、交叉引用），基线从 6→10 文件并记录期望值/最小表格与材料数；`calibrate --compare-baseline` 在 CI 中作为门禁。
- `judge_for_project` 复用项目上下文，1 与 100 条需求的批量查询 SQL 次数恒定为 1；评估报告新增 `manual_edit_rate` / `issue_density` / `boq_match_rate` 三项质量指标及口径说明。

## 5. 前端闭环与可观测性

- 查重 UI 枚举与后端契约对齐（`scope=project|history`、`mode=text|structure|semantic|image|all`），历史范围必须传 `source_project_id`；统计卡片从命中结果推导；新增前后端出站契约双向测试。
- 待我审批下拉新增“工作流待审”分区，跳转项目 Agent 页；知识库管理新增文档列表与检索预览（含文档/页码/标题来源）。
- 任务日志统一携带 `job_id`/`kind`/`project_id`/`worker_id` 与失败模板；`global_metrics` 扩展至 10 项（含 `workers_running`、`queued_jobs`、`oldest_queued_age_seconds`、`stale_running_jobs`）；新增公开的 `/health/live`（不查 DB）与 `/health/ready`（DB/模型/Web 产物），uvicorn access log 注入 request-id。
- 容器：镜像内置 `pg_dump`，HEALTHCHECK 指向 `/health/live`，compose 设置 45s 优雅停止、CPU/PID 限制、`cap_drop: ALL` 与 `no-new-privileges`，并保留非 root 运行；未加 `env_file:`（按批准决定，环境显式传入）。

- 远端 CI：最终 run `45389917297` 在最终 HEAD 上 **9/9 jobs 全部成功**（Python lint/tests、Web、真实 PG、DOCX CJK golden、Docker 镜像与 compose、依赖审计、Bandit、密钥扫描）。

## 7. 已知边界

- 回归语料仍为合成脱敏样本，真实标书召回率需在用户提供脱敏样本后再校准。
- 远程插件市场与 OS/容器级隔离、质量报告导出与批次看板仍按既有决定暂缓。
- compose 未使用 `env_file:`；镜像 digest 固定与只读根文件系统留待后续评估。
- 本地缺少 PostgreSQL / Docker / LibreOffice，相关验证由 CI 专用 job 覆盖。

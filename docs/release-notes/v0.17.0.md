# BidCraft v0.17.0

数据库层从「仅 SQLite」升级为 SQLite/PostgreSQL 双后端。默认行为不变；设置
`BIDCRAFT_DB_URL` 即切换到 PostgreSQL。API/Worker 分离部署（v0.12.0 引入）终于
有了共享数据库的可选方案。

## 本版内容

- **配置与连接**：新增 `BIDCRAFT_DB_URL`；`postgresql://`、`postgres://`、
  `postgresql+psycopg://` 三种写法统一归一到 psycopg 3（新增 `postgres` extra）。
  健康检查 `safe_dict` 增加脱敏后的 `db_backend` / `db_url`，不泄露口令。
- **引擎与迁移**：按方言设置连接池（PG 打开 `pool_pre_ping` 与 10s 连接超时）；
  历史补列 `_migrate_columns` 只在 SQLite 执行；跨进程迁移锁在 PG 上改用会话级
  `pg_advisory_lock`，多台机器同时启动也不会并发跑 DDL。修复了一个只会在 PG
  暴露的问题：Alembic 连接串原来用 `str(URL)` 生成，密码会被渲染成 `***`。
- **外键完整性**：SQLite 从未开启外键，删除路径漏掉的子表只是静默变孤儿；PG
  强制外键会直接拒绝删除。新增 `purge.delete_user_rows`，账户注销、超管删用户、
  删子账号统一走它，显式清理成员关系、订单、发票、会话、项目及其全部子表。
  `AuditLog.user_id` 仍按留存红线不清理。
- **备份**：`bidcraft backup` 按后端选择 SQLite 在线备份或 `pg_dump`（口令走
  `PGPASSWORD`，不进命令行）；`backup-verify` 两种格式都能校验。同时修复了
  `backup-verify` 命令被误绑到 `backup-prune` 的既有 CLI bug。
- **任务队列可移植性**：认领语句抽出为可编译校验的独立函数，明确其并发正确性
  依赖外层 `status='queued'` 重检；未使用任何 SQLite 专有函数。

## 说明

SQLite 仍是默认后端，不安装 `postgres` extra 不受影响。SQLite → PostgreSQL 的
数据迁移需要用户自行用 dump/restore 或 pgloader 完成，本版不提供自动迁移工具，
也不改动既有 SQLite 数据库。完整用法与行为差异见 `docs/postgresql.md`。

- 后端：**877 pytest**（869 + 8），ruff 全绿；其中 `tests/test_postgres_support.py`
  为无需服务器的方言单测，`tests/test_postgres_integration.py` 为 opt-in 真实 PG 套件。
- 真实 PostgreSQL 16（Docker）集成验证通过 8 项：建表/migration head、中文与
  JSON CRUD、6 线程并发原子认领（无重复、令牌每次刷新）、fencing 拒绝旧令牌、
  导出门禁读已确认章节、外键删除全链路、咨询锁串行化、`pg_dump` 备份。
- 前端：lint 0-0 / 188 tests / build 0（本版无前端功能改动，仅版本号）。

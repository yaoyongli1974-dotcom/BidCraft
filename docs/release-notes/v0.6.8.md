# BidCraft v0.6.8

桌面客户端归档后，「不演进」不等于「不可重建」：把它的依赖固化成配方，而不是靠构建机上
碰巧装了什么。顺带把过时的自我定位改掉。

## 本版内容

- **冻结配方（`pyproject.toml`）**：新增两个 extra，仅用于可复现地重建既有产物，不随新功能演进：

  ```toml
  desktop = ["qtpy>=2.4", "PySide6>=6.6", "pywebview>=5.1"]
  build   = ["pyinstaller>=6.6"]
  ```

  精确版本由 `uv.lock` 锁定，重建命令：`uv sync --frozen --extra desktop --extra build`。
- **构建脚本查齐四依赖**：`packaging/build_pyinstaller.sh` 原先只检查 `import PyInstaller`，
  PySide6/qtpy/pywebview 全靠隐式约定。现在用 `importlib.util.find_spec` 检查四个模块，缺失时
  直接打印上面那条 sync 命令并退出。
- **`desktop-release.yml` 不再临时装依赖**：三个平台统一改为 `uv sync --frozen --extra desktop --extra build`；
  沿用原产物配方，不引入 api extra。
- **`attach_to_release` 默认关闭**：该 workflow 仍可手动重建，但安装包默认只作为 Actions artifact
  留存。此前手动选 tag 重建会把安装包重新附加到 Release——那等于自动恢复分发，重新激活
  Qt/PySide6 的 LGPL-3.0 再分发义务。要恢复分发必须显式勾选。
- **元信息去「弱电」**：`description` 改为「投标文件编制系统：招标解析 → 事实台账 → 规则引擎 →
  大纲/正文 → 合规核对 → 清单报价 → DOCX/PDF 导出」；`keywords` 换成
  `tender`/`bid`/`bidding`/`boq`/`docx`/`rules-engine`/`compliance`，删掉 `weak-current`
  （行业包早已是 8 个，不是弱电专用）。README 标题同步去掉「弱电」。
- **新增 `tests/test_desktop_recipe.py`**（5 例）：守住 extra 声明、`uv.lock` 锁定五个桌面包、
  元信息不再出现弱电定位、构建脚本查齐四依赖、workflow 仅手动触发且默认不重新附加 Release。

## 验证

- 后端：**723 passed**，ruff 全绿。
- 前端：lint 0 errors / 0 warnings，**134 tests**，build exit 0。

  成功；版本为 PySide6 6.12.0 / qtpy 2.4.3 / pywebview 6.2.1 / pyinstaller 6.22.3。

## 说明

本版仅服务端；不提供桌面安装包。桌面客户端冻结于 v0.6.3，自行构建或再分发须遵守
Qt/PySide6 的 LGPL-3.0 动态链接与可替换要求，见仓库 `NOTICE`。

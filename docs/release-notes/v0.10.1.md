# BidCraft v0.10.1

注册协议的「同意」必须由用户明确提交，不能再靠接口默认值替客户端做主。

## 本版内容

- **后端不再默认同意**：`RegisterRequest.accept_terms` 默认值由 `True` 改为 `False`。
  客户端不传该字段或显式传 `false`，注册接口一律返回 400「请先阅读并同意服务条款与隐私政策」，
  不会创建账号。要注册必须明确提交 `accept_terms: true`。
- **前端共享默认值同步**：`AuthContext.register` 与 `lib/api.ts` 的 `register` 中
  `acceptTerms` 默认值由 `true` 改为 `false`——即使将来有页面用默认参数调用，也不会隐式勾选同意。
  （注册页 `RegisterPage` 的勾选框此前已默认未勾选，并已在提交时校验。）
- **同意留痕保持不变**：注册成功时按提交值记录 `terms_version`（缺省用当前法律文件版本）与
  `terms_accepted_at`（北京时间口径落库），`/legal` 相关接口可校验是否最新。本版补了专门测试
  覆盖「缺省拒绝 / 显式 False 拒绝 / 显式 True 记录版本与时间 / 自定义版本按提交值留痕」。
- **旧客户端不再被兼容**：不提交同意动作的旧客户端注册会被拒绝——这是有意行为，符合合规要求，
  不做「默认同意」的向后兼容。冻结的桌面客户端 `register()` 同样不提交同意，因此也会注册失败；
  客户端已冻结不更新，测试改为断言「旧客户端缺同意时注册被拒」以固化这一口径。

## 影响与迁移

- 这是接口行为变更：任何以「不传 accept_terms」方式注册的调用方都必须改为显式提交
  `accept_terms: true`。仓库内相关测试注册夹具已统一补齐。
- 已注册用户不受影响；本版不改动数据库结构。

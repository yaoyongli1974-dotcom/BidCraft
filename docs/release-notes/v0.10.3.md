# BidCraft v0.10.3

身份上下文（`ContextVar`）的规范清理：请求身份不再可能在请求结束后滞留。

## 本版内容

- **`set_current_user` 返回 ContextVar token**：调用方拿到 token 后可精确还原身份。
- **新增 `reset_current_user(token)`**：把身份上下文恢复到设置前的值。
- **认证中间件用 `try/finally` 包裹**：`token = set_current_user(payload)` 之后，无论请求正常返回还是中途 403 早返回，都在 `finally` 里 `reset_current_user(token)`；401（未登录）发生在 set 之前，无需 reset。
- **后台任务不受影响**：worker、jobqueue、两处后台线程从不读这个上下文，一律显式传 `user_id` / `project_id` / 权限；CLI/MCP 无身份上下文，审计记 `system`（行为不变）。这一条本就满足，本版在注释与文档里写明边界。

## 为什么做

`ContextVar` 缺 reset 时，为某个请求设置的身份可能泄漏到同一 context 里后续执行的工作（如同任务里的其它处理、响应之后的收尾代码）。虽然 Starlette 的 `BaseHTTPMiddleware` 在独立 task 中运行、外部难以观测，但「设置—还原」成对出现是异步/线程边界的正确写法，本版补齐。

## 不变

- URL、请求/响应格式、业务行为零变化。
- 各路由读取 `current_user()` 的语义不变——reset 只发生在请求结束后。
- 审计身份优先级 `actor > current_user() > system` 不变。

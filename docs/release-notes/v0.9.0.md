# BidCraft v0.9.0

上一版把 API 拆成了分层结构。这一版处理代码审查提出的三项 P1 数据层问题：数据库迁移机制、报价金额精度、外键与关联清理。三项都按「最小侵入、可回滚、保留既有契约」的原则推进。

## 本版内容

### 1. 数据库迁移引入 Alembic（P1）

- `create_all` + `_migrate_columns` 继续作为**历史基线**：旧库先由这套机制收敛到当前 schema，再 `stamp` 到 `0001_baseline`；两者不再二选一。
- 新增 `bidcraft/migrations/`，`env.py` 运行时从引擎注入数据库 URL（不依赖固定 `alembic.ini` 路径），`render_as_batch=True` 适配 SQLite 的改类型/重命名。
- `init_db()` 启动顺序：建表 → 历史补列 → Alembic `upgrade head`；迁移后用 `engine.dispose()` 回收连接，避免缓存旧 schema。
- 跨进程迁移锁 `settings.home/.migration.lock`（fcntl 排他锁，Windows 降级无锁）：`serve` / CLI / MCP 同时启动不会并发跑 DDL。
- **第一个真实 revision `0002_quote_basis`** 演示「新增列走 revision」路径，写成幂等（列已存在则跳过），避免与 `create_all` 冲突。今后新增/改类型/重命名/加索引一律写 revision，不再往 `_migrate_columns` 的 additions 字典里加东西。
- 新增 `bidcraft db` 迁移测试：fresh 库记账、重复 init 幂等、老库先收敛再 stamp、迁移连运行时注入的库。

### 2. 报价金额 Float → Decimal（P1）

- 新增统一金额服务 `bidcraft/services/money.py`：**内部全程 `Decimal` + ROUND_HALF_UP 商业舍入**，仅在 JSON / API / Excel 出口转回 float，保持前后端契约与现有金额测试不变。
- 单价 4 位、金额与税额 2 位、工程量差异 6 位；`sum_amounts()` 逐行转 Decimal 再累加，消除 `0.1 + 0.2 = 0.30000000000000004` 这类累计漂移。
- `boq.py` 的报价、税额、汇总、调价、汇率折算、定额套价全部改走金额服务；审批门槛判定不受影响（出口仍是 float）。
- **报价版本新增不可变计算依据 `basis`**：保存时冻结每行的工程量数量（`sheet!row → qty`）与当时的税率、币种、汇率、调价系数、舍入位；单价继续存 `prices`，结果存 `summary`。保存后再改项目策略，旧版本的依据不变，可审计、可复算——此前只存算好的结果，复算会随当前策略漂移。

### 3. 外键与关联清理（P1，第一阶段）

- 现状说明：28 处 `ForeignKey` 声明但 SQLite 从未开 `foreign_keys=ON`（纸面约束），且项目/用户/账号注销的删除路径普遍漏清理关联表。本版先做**补删除路径 + 孤儿检测**，开启外键强制留到数据确认干净之后。
- 新增 `bidcraft/services/purge.py`：`delete_project_rows()` 集中清理全部 18 类关联行（含此前漏掉的 `FactCitation` / `BidPackage` / `BoqQuoteVersion` / `JobEvent`），`audit_logs.user_id` 的悬挂是注销追责的有意设计，**不在清理范围**。
- 项目删除路由改为调用共享清理助手，不再各入口各写一份；审计详情附带各类删除条数。
- `ORPHAN_RULES` + `find_orphans()` / `clean_orphans()`：只读检测与可选清理孤儿引用（子行 ID 指向已不存在的父行），排除审计 `user_id`。
- 新增 CLI `bidcraft db-orphans`（默认只报告，`--apply` 才删除）——这是开启外键强制前的数据体检手段。

## 说明

- 三项均保持 URL / 请求响应格式 / 业务函数 / 数据结构不变（报价版本详情新增 `basis` 字段属附加，不破坏既有字段）。
- 留存红线：投标项目、报价版本、审计与财务数据不简单 `ON DELETE CASCADE`；审计 `user_id` 故意留悬挂供注销追责；`BoqQuoteVersion` 随项目删除时由调用方写审计。
- 外键强制（`PRAGMA foreign_keys=ON` + 整表重建补 FK）作为下一阶段，需先通过 `db-orphans` 确认历史数据无孤儿再启用。

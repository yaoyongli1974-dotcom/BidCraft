# BidCraft v0.21.0

本版是判定引擎的深度改造，核心目标不是加功能，而是让每一个投标条款判定都具备可靠的规则依据、准确的证据关联、可追溯的人工复核和安全的交付门禁。R01–R07 七项均已落地。

## R01 复合条款原子拆分闭环（P0）

- `split_atoms()` 从「按标点切分」升级为「标点 + 中文连接词双切分」，识别 `并/并且/且/同时/以及/并提供/并满足/还须/均应/分别/其中` 等，长词优先避免误切。
- 不机械切分：连接词后的片段仅在有独立约束或主体时才真正拆开（「一级资质并保持有效」不会被切开）；每个原子带独立编号 `A01/A02…` 与 `source_start/source_end` 偏移，原文可追溯。
- 修复前导正则吞掉数值首位数字的 bug（「2小时内响应」不再变成「小时内响应」）。
- `atom_split_is_ambiguous()` **真正进入 `judge()` 判定流程**：多原子需求先做原子级汇总——任一原子明确不满足 → 整条不满足；部分满足部分缺失 → 部分满足；全满足且证据充分 → 满足；拆分歧义且无具体结论 → 人工复核。不再出现「一个原子满足就把整条判满足」。

## R02 多种约束混合的主体关联（P0）

- `extract_constraints()` 不再用整条文本第一个 family 作所有约束的默认主体；每条方向约束按局部子句 `_local_family()` 独立推断主体。
- 「近三年3项业绩，且带宽≥1000Mbps」中业绩=achievement、带宽=bandwidth 各归各族，不再相互替代：500台设备/500MHz处理器不能回答1000Mbps带宽，3项业绩不能回答3年质保。
- `Constraint` 增 `metric/subject/object/quantity/source_span` 追溯字段（带默认值，兼容既有构造）。

## R03 业绩时间窗按招标截止日期实际校验（P0）

- 新增 `resolve_deadline()`：优先从事实台账读招标截止日期（`tender_deadline`/`bid_deadline`/`投标截止时间` 等 key），兜底读 `Project.meta`(JSON)；**不使用服务器当前时间**，两者都拿不到则转人工复核。
- 逐项业绩按四位年份日期校验，区分签订/开工/竣工/验收日期类型；「近三年」按截止日期换算 cutoff，早于 cutoff 的业绩不计入。
- 一条过期不否定其他在窗内的业绩；有效数达到约束阈值即判定满足；全过期 → 不满足；缺截止日期或签订日被当完成日 → 人工复核。
- 时间窗结果**进入最终判定**（不再只写 evidence）。相对时间窗（近五年6项）沿用旧兼容口径。

## R04 单位与约束提取完整性（P1）

- 方向约束正则改为复用完整 `_UNITS` 表，消除「单位已注册却提取不到」的不一致（GB/TB/MB/s/GHz/Kbps 等全部可提取）。
- 新增二进制容量单位 `KiB/MiB/GiB/TiB`（1024 进制）与十进制 `KB/MB/GB/TB`（1000 进制）分开登记；`1000GB == 1TB`、`500GB < 1000GB` 断言真实 state；`Mbps` 与 `MB/s` 跨量纲不相等 → 人工复核；未知单位不自动兼容。

## R05 彻底消除 requirements API 的 N+1（P1）

- 新增 `ProjectRequirementContext` 与 `build_requirement_context()`：单请求一次加载大纲并建 `node_id→heading` 索引，判定与展示共享。
- `_requirement_payload()` 彻底移除逐条 `db.get(OutlineNode)`；`/requirements` 与确认接口共用请求级上下文，项目间隔离、大纲更新后下次请求即见新值，保持返回结构兼容。

## R06 统一 CI + 真实 PostgreSQL 集成（P1）

- CI 前端安装改严格 `npm ci`（删除 `npm install` 回退，锁文件不一致直接失败），与 Dockerfile 一致。
- 新增 `postgres` job：service container 启动独立 `postgres:16-alpine` 临时库，设 `BIDCRAFT_TEST_PG_URL` 跑 8 个真实集成用例（建表/迁移、CRUD、并发认领、fencing、导出门禁、外键删除、咨询锁、备份）；用 junitxml 断言 tests≥8 / skipped==0 / failures==0，**PG 测试不得静默跳过**，否则 CI 失败。保留 SQLite 全量 job。

## R07 门禁审计顺序 + ★确认权限（P1）

- **修复真实 bug**：`enforce_export_gate()` 的 `export.force` 审计从章节门禁检查之前移到之后——强制导出因章节未确认失败（409）不再留下成功审计。
- **★ 条款最终确认权限收紧到 owner/admin**：编辑人员可提交响应内容与复核说明，但 ★ 实质性条款的最终确认必须项目负责人/超管完成（后端强制校验，editor 403），实现「编制 ≠ 确认」。前端隐藏按钮不代替后端权限。

## 兼容性与数据库

- 无数据库结构变化，无需迁移脚本（截止日期走事实台账 + meta，不新增列）。
- 所有新增 `judge()` / `requirement_issues()` 参数均为可选，既有调用点行为不变；API 返回结构未变。
- 桌面客户端保持冻结，本版无安装包、不附加任何 Release 资产。

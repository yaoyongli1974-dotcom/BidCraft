# BidCraft v0.20.1

任务书 T01–T08 的可靠性/可重复性改造。基于 v0.20.0 的既有能力做收尾：把"已经做了但不够严谨"的几处补成可验证、可举证的形态。API 结构保持向后兼容。

## 改造项对照

| 任务 | 结论 | 本次改动 |
| --- | --- | --- |
| T01 人工复核与导出控制 | 既有实现已覆盖主干 | 补验收测试：★ 未确认阻止导出、强制导出独立权限（editor 403）、原因必填、完整审计（越过条款 + 原始判定）、人工确认后 SUB 阻断消失 |
| T02 数值单位/量纲 | 已禁止缺单位默认兼容，**但只有二态** | 新增三态 `unit_relation()`：compatible / incompatible / unknown；补**存储容量**量纲（B/KB/MB/GB/TB，与带宽、字节率、频率互不可比）；统一换算关系单点声明 |
| T03 复合条款原子拆分 | 原按标点机械切分 | `split_atoms()` 保留原文字句、稳定编号、主体归属与命中约束标签；连接词/无法抽约束的片段打 `ambiguous`，上层可转人工复核（`atom_split_is_ambiguous()`） |
| T04 多候选数值关联 | 原取第一个同量纲命中 | `_evaluate_one()` 收集**全部**候选，各自比较并按主体词族上下文打关联分；结论一致才采纳，冲突时取关联分更高者，仍冲突转 `unclear`（人工复核），不再"取第一个/取最大值" |
| T05 业绩时间窗判定 | 原仅比数字 | `_time_window_signals()` 只在时间窗与业绩对象**同一子句**时报信号；有明确完成日期仅提示；业绩子句缺日期/时间窗转人工复核；一处短窗不否定全部业绩 |
| T06 API 大纲加载 | 每条 requirement 各 `load_outline` 一次（N+1） | 新增 `get_outline_cached()`，`/requirements` 单请求内按 project_id 预加载并共享；缓存按请求创建、请求间隔离，大纲更新后下一个请求必然重载 |
| T07 PostgreSQL 迁移锁 | 咨询锁失败时降级为本地文件锁 | **fail-closed**：获取失败直接阻止迁移（RuntimeError），绝不降级——文件锁只在单机有效，多实例并发 DDL 正是要避免的；保证失败/成功/body 抛错路径都释放锁并关闭连接 |
| T08 Docker 构建 | `npm ci || npm install` | 改为严格 `npm ci`；对齐 `package-lock.json` 与 `package.json` 版本（原 lock 为 1.0.0）；真实 `docker build` 通过 |

## 兼容性

- 所有 API 响应结构未变；`_requirement_payload` 新增可选参数 `outline_cache`，默认值保持原行为。
- `_unit_compatible()` 保留为 `unit_relation() == compatible` 的布尔视图，既有调用方不受影响。
- 数据库结构**无变化**，无需迁移脚本。
- 未创建 GitHub Release（遵循发版惯例）；打 annotated tag v0.20.1。

# v0.32.1 发版说明（报价审批链规则命中条件）

本版本在 v0.32.0 AI 技术标编制引擎闭环之上，补齐路线图中「报价审批链规则命中条件」。审批阶段可在保留原有金额门槛、包件/币种白名单的前提下，追加一组可选 AND 规则，按报价版本真实上下文决定该级是否生效；旧审批链行为、审批记录 stage 原始索引语义与导出门禁均未改变。分支 `feature/v0.32-ai-engine`，实施证据见 `docs/development/v0.32.1/01_APPROVAL_RULES_REPORT.md`。

## 1. 规则字段与操作符

- 字符串字段：`package_id`、`currency`；数值字段：`total_amount`、`boq_rows`、`priced`、`unpriced`、`match_rate`。
- 操作符：`gte`、`lte`、`eq`、`ne`、`in`、`not_in`、`contains`。
- 每个阶段最多 20 条规则，按 AND 求值；非法字段、非法操作符、布尔值、非有限数、空列表、超长字符串与非 dict 条目一律丢弃，不静默篡改有效规则。
- 未知上下文按「规则满足」处理，沿用既有 over-review 保守口径：宁可多一级审批，不漏审批。

## 2. 报价摘要数值规则

- `boq_rows`、`priced`、`unpriced`、`match_rate` 取自报价版本 `summary`，仅在 BOQ 报价审批链路传入（版本详情、审批、待我审批）。
- 商务标审批仍使用旧三字段上下文（`total_amount`/`package_id`/`currency`），不引入跨业务口径。
- 阶段过滤与 `approval_stage`、`approval_stage_count`、`pending_for_user.stage/stage_count` 同步；审批记录仍写原链索引，不改变审计语义。

## 3. 前端配置

- 审批链弹窗每级新增「规则条件」区：字段、操作符、值输入，规则以胶囊展示并可移除；保存时随 `approval_chain` 一并 PATCH。
- 前端与后端共用同一套白名单、上限与归一化口径；未知值保留 `null` 或走保守命中，不伪造 0、不伪造「已验证」。

## 4. 数据与 API 兼容

- 无新表、无新列、无历史迁移改动：规则存于 `Project.meta.approval_chain` 的阶段字典可选键 `rules`；API schema 本就是 `list[dict[str, Any]]`。
- API 路由数保持 274，Pydantic 请求模型保持 93；旧链、金额门槛、包件/币种条件、多级会签/或签均保持原行为。

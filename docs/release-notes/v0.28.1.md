# BidCraft v0.28.1

发版主题：v0.28.0 之后的**第二轮质量加固与运维补齐**。本版不含新业务域，集中修复两轮全量分析发现的回归、升级兼容性与运维可观测性缺口；接口行为保持向后兼容。

## 本版内容

### 1. 升级兼容性与数据完整性

- 新增 Alembic `0009_v028_schema_parity`（down=`0008_job_queue_indexes`）：补齐 `plugins` 的 `scope/owner_id/allow_private_net` 等 7 列，以及基线之后遗漏的 5 个 requirements 列；为 `jobs.owner_id` 建索引并回填 `payload->>'owner_id'`，新增 `pending_charges` 表；升级与降级均幂等。
- 修复 PostgreSQL 从 v0.27 升级到 v0.28 时插件列缺失导致查询失败的问题；CI 增加 Alembic 单头扫描，不再硬编码 head 版本号。
- 修复 `jobs.owner_id` 入队回归：`generate_all` 与图片批处理现在写入 `owner_id`，按用户背压不再被绕过；模型列的归属推导增加 `payload['user_id']` 与项目所有者回退。
- PostgreSQL 旧 schema 升级路径增加 opt-in 测试：回退到 0008、构造 v0.27 形状数据与旧 job payload，再执行升级并断言列、索引、回填与版本号，结束后恢复 head。

### 2. 计费可靠性与对账

- `pending_charges` 现在有完整生命周期：扣费先落账、生成完成后原子结算；崩溃/重启造成的未结算窗口由启动恢复 + reaper 每 5 分钟周期扫描兜底。
- 新增环境变量 `BIDCRAFT_PENDING_CHARGE_TTL`（默认 1800 秒）与 CLI `bidcraft reconcile-charges [--older-than N]`，运维可手动触发对账并打印结算数量。
- 非整除 VIP 章节退款改为整数精确计算（`credits - ceil(credits*written/chapters)`），避免少退。

### 3. 运行时、安全与部署

- 工作流审批通过后真正创建新的 agent Job 并写审计，不再让 run 永久停在 `running`；驳回不排新任务。
- 同步「运行评估」现在返回完整 findings，前端运行后主动刷新最新报告，不再误报「未发现质量问题」。
- 限流器增加 TTL + LRU 硬上限，避免键空间无界增长；新增 `BIDCRAFT_PUBLIC_ORIGIN` 供反向代理场景的 CSRF 同源判定；`BIDCRAFT_TRUST_PROXY` 控制代理头信任，`--no-proxy-headers` 防伪造。
- 请求 ID 中间件移到最外层，早退的 401/403/429 也带 `X-Request-ID`。
- 备份支持 `BIDCRAFT_BACKUP_DIRS` / `--include-dir` 纳入数据目录并生成 SHA256 清单，`backup-verify` 校验文件哈希；新增 opt-in 恢复演练（`BIDCRAFT_RESTORE_DRILL=1`）。
- 新增 `deploy/nginx.conf.example`（`limit_req_zone` / `limit_req` 与真实 IP 透传说明），补齐多 worker 场景的应用层限流边界。
- 清理语义修正：项目删除后审计行改为解绑保留（`audit_logs=0`、`audit_logs_detached=n`），重复支付通知仅在首次标记成功时写审计。

### 4. 前端、文档与测试

- 管理端「运行状态」直接渲染后端 6 个真实全局指标键，使用项目/任务/发现项的标准状态中文映射，移除虚构指标与过时脚注。
- 插件 scope 字段在前端 normalizer、编辑弹窗与列表标签完整往返，编辑个人插件不会被降级为全局。
- 新增导出模板选择器并持久化到项目模板接口；审批类型使用真实中文档位标签；管理控制台滚动条与激活标签可见性优化。
- 文档口径同步：计费崩溃窗口与对账 TTL、备份/恢复演练、全局指标 6 键、nginx 限流示例、质量报告导出与批量看板明确标记为暂缓（格式与脱敏口径未定）。

## 数据库变更

- Alembic `0009_v028_schema_parity`（down=`0008_job_queue_indexes`），幂等升级/降级已覆盖；当前单头为 `0009_v028_schema_parity`。
- 新增 `PendingCharge` 模型与 `jobs.owner_id` 索引（`ix_jobs_owner_id`）；存量数据由迁移回填。

## 兼容性

- 无破坏性接口变更；API 路由模块仍为 18 个，路由总数 247（未新增路由）。
- 新增环境变量均有安全默认值：`BIDCRAFT_PENDING_CHARGE_TTL`、`BIDCRAFT_PUBLIC_ORIGIN`、`BIDCRAFT_BACKUP_DIRS`、`BIDCRAFT_RESTORE_DRILL`。
- 新增 CLI 子命令 `bidcraft reconcile-charges`；既有命令参数不变。
- SQLite / PostgreSQL 双后端通用；桌面客户端继续冻结（终止于 v0.6.3），无 Release 附件。

## 已知限制

- 真实招标文件基线校验仍需项目方提供样本并人工确认指标口径；仓库内只提交聚合基线与指纹。
- 远程插件市场自动安装、容器/系统级隔离继续暂缓。
- 全局运营指标通过 `/admin/health` 暴露，尚无独立聚合端点；待审批工作台的跨项目工作流待办仅有项目内入口。
- 质量报告导出与批量评估看板因格式/脱敏口径未定继续暂缓，文档中已明确标注。
- LLM 语义匹配器仍是可选增强，默认规则匹配器为基线。

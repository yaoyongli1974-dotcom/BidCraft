# BidCraft v0.20.0

两个最高优先级（P0）修复：**人工复核状态与导出权限关联**、**数值单位缺失导致的错误比较**。
两者都是"看起来能过、实则被误放行/误拦"的判定缺陷，本版把它们收紧为确定性规则。

## P0-A：人工复核按条款重要性分级，★ 未确认不得交付

此前四态里的「人工复核」一律 `info`、不阻塞导出。这意味着一条带 ★ 的实质性条款即便没被
可靠验证，也可能被直接导出——与实际投标业务冲突。本版改为**按重要性 + 确认状态分级**，
而不是把所有 review 一刀切改成 blocking：

| 条款 | 人工复核（未确认）的门禁 | 说明 |
|---|---|---|
| ★ 实质性 | **blocking**（阻塞） | 未确认不得正式交付；确需导出走强制导出，须负责人独立授权并留完整审计 |
| ▲ 实质性 | critical（严重提示，不阻塞） | 原则上需人工确认，但不拦交付 |
| 普通条款 | info（可见，不阻塞） | 延续既有口径 |

- 强制导出仍要求 owner/admin 独立授权 + ≥4 字原因（沿用既有 force 通道）；
  新增强制导出审计 detail 里的 `overridden_substantives`，逐条记录被越过的 ★ 条款
  编号、标记、原文、原始判定与原因——越过也留痕，可追溯。
- 人工确认「已响应 / 不适用」时，服务端**快照原始自动判定结果**
  （`response_verdict` / `response_verdict_label` / `response_verdict_reason`）落库，
  连同人员（`audit()` 当前用户）、时间、原因一起写入审计——确认前的真实判定不再丢失。

## P0-B：单位缺失不认定量纲一致，禁止跨量纲比较

此前 `_unit_compatible` 里 `if not left or not right: return True`，导致正文里裸写的数值
被套用约束单位比较。典型误判：招标要求"带宽不小于 1000Mbps"，正文"500 台设备、带宽
1000Mbps"——若先遇到裸写的 500，会被当成 500Mbps 判不满足。本版：

- **单位缺失 → 不认定量纲一致**。任一侧无单位即不可比，绝不套用对方单位。
- **登记明确的换算关系**：带宽（bps/Kbps/Mbps/Gbps → Mbps）、字节率（B/s…GB/s → MB/s，
  与带宽**不同量纲**）、频率、数量、时长（分钟…年 → 月，保证 5 年 == 60 个月）、
  长度、电压、功率、电流、百分比。同量纲归一后比较（1000Mbps == 1Gbps）。
- **禁止跨量纲比较**：MHz / MB/s 与 Mbps 不同量纲，不因"100 < 1000"就判违反。
- **单位不明确 → 人工复核**：正文有数值但单位缺失/跨量纲时转 `unclear` 态，
  既不按"满足"放行、也不按"不满足"拦死，走 review 门禁（★ blocking / ▲ critical / 普通 info）。
- 用户点名的四组场景全部进回归：500 台+1000Mbps、500MHz+1000Mbps、1000Mbps vs 1Gbps、
  1000Mbps vs 100MB/s（后者不得认为相等）。

## 兼容性

- 数据库增量列由启动时幂等迁移补齐（`requirements` 表 3 列）。
- `GET /requirements` 增加 `response_verdict` / `response_verdict_label` / `response_verdict_reason`；
  前端类型与透传同步，旧数据缺字段按空处理。
- 普通 blocking 风险的强制导出行为不变；本次新审计字段只在越过 ★ 条款时出现。

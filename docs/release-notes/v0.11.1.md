# BidCraft v0.11.1

任务队列改成 DB 驱动后，还有两个多实例场景会让同一任务被执行两次。本版给认领加上
fencing 令牌，把「只有一个 worker 能真正写任务状态」这件事做实。

## 本版内容

- **认领令牌（claim token）**：每次原子认领都刷新一枚 36 位令牌写进 `jobs.claim_token`。
  租约被回收并重新认领后令牌必然不同，旧 worker 不再是当前持有者。
- **关键写入全部校验令牌**：心跳续租，以及 6 个 worker（生成、导出、合规核对、配图、
  知识库重建、任务兜底收尾）对任务状态/进度/结果/退款的每一次写入，都改为
  `fenced_job()`——令牌不匹配就直接跳过，旧 worker 再也不能覆盖新 worker 的运行结果。
  退款仍叠加 payload 的 `refunded` 幂等标记。
- **启动恢复不再误杀活跃任务**（P0-1）：`recover_on_startup()` 只回收**租约已过期**
  的 running 任务；未过期的视为其他实例正在执行，交给 reaper 过期后再处理。
  多实例部署时，某实例启动不再把别的实例正在跑的任务重新排队。
- **心跳携带令牌**（P0-2）：`UPDATE ... WHERE ... AND claim_token=:token`，令牌失效时
  旧 worker 停止续租，新持有者的心跳成为唯一延长租约的来源。

## 语义

- **至少一次执行（at-least-once）**：租约过期后旧 worker 的业务代码可能仍在飞，
  本版保证的是它的**写入/副作用不会落到新任务上**，并不宣称取消正在运行的模型调用
  或做到 exactly-once。要彻底避免重复执行，需要逐章幂等键（后续专项）。
- 数据库增量列由 Alembic revision `0004_claim_token` 幂等补齐；Alembic head 同步更新。

## 验证

- 后端：**837 passed**（新增 7 例：启动恢复只收过期租约、未过期 running 不动、
  令牌刷新、fenced_job 拒绝旧令牌、requeue/fail 清令牌、兜底收尾被 fencing、
  runner 运行在绑定的认领上下文内、心跳随令牌失效退出），ruff 全绿。
- 前端：无功能变更（仅版本号同步），lint 0-0 / 169 tests / build 0。
- 覆盖点：fencing 助手、令牌刷新与清理、心跳失效、启动恢复不误杀、兜底收尾不越权。

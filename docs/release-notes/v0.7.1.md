# BidCraft v0.7.1

「正文里的每个数字都必须来自本项目」这条约束，此前只活在提示词和生成规则里。本版把它
变成界面上看得见、点得开的绑定关系：**来源追溯**与**需复核标记**。

## 本版内容

- **正文来源追溯**：章节预览里每个命中事实台账取值的片段都会高亮（虚线 + 信息色）。
  点一下展开来源卡片：台账字段名与键、正文引用值、台账当前值、**招标原件原文与页码**。
  嵌套在代码块里的内容不参与匹配。
- **需复核标记**：台账字段被改写后，仍写着旧值的章节自动标记——侧栏章节条出现「需复核」、
  章节头部显示「来源 N 处 · M 处待复核」、台账保存后弹出提示列出受影响章节。
  正文按新值改完并保存，标记自动消失（不依赖人工清除）。
- **数字按独立数字对齐**：`150` 不会命中 `50`，`1.90` 不会命中 `90`，避免大量假阳性。
  过短（如「1」）或纯占位（「无」「其他」）的取值不作为追溯依据。
- **新接口**：`GET /projects/{ref}/chapters/{node_id}/citations`（本章引用）、
  `GET /projects/{ref}/citations`（全书引用与待复核章节）；`PATCH /projects/{ref}/facts/{key}`
  的响应新增 `stale_sections`，直接告诉前端这次改动影响了哪些章节。
- **重扫时机**：章节保存、单章生成、全书核对三处都会重建引用（核对时全量重扫），
  因此模型生成的正文无需用户逐章打开也能被追溯到。
- 边界：**不自动改写正文**。台账与正文不一致时只提示人，避免用"看起来对"的值覆盖作者判断。

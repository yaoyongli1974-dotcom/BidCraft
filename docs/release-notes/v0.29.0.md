# BidCraft v0.29.0

发版主题：**对标易标专项改造（八批）**。本版按照 `docs/development/BIDCRAFT_YIBIAO_REFACTOR_REPORT.md` 的审查与实施结论，对判定、生成、DOCX、商务标、知识库、Agent、前端与回归链路做系统性加固；不引入新业务域，核心业务口径不变。

## 本版内容

### 1. 计费可靠性与数据迁移

- 新增 Alembic `0010_batch1_billing_reliability`（down=`0009_v028_schema_parity`）：补齐 `PendingCharge.billing_account_id`，并按 `owner_id → user_id → 项目 owner` 的 COALESCE 链回填历史 `jobs.owner_id`（PostgreSQL / SQLite 双实现），可升级、可降级。
- 生成任务失败终态（重试耗尽、reaper、启动恢复）按 `done_steps` 中 `chapter:` 数量幂等退款；成功、异常与中止路径统一退款口径并带 `refunded` 标记。
- `settle_pending_charge()` 改为条件占claim，避免与 TTL 对账并发重复退款；对账跳过同项目仍有活跃 Job 的 marker，子账号删除时按付款账号退款；无付款账户的 marker 保留待重试。

### 2. 实质性条款与判定引擎

- 复合业绩原子从完整条款继承时间窗，修复「近三年 + 过期业绩」被误判为满足；项目类型识别限定在业绩条款，避免污染带宽等参数。
- `和/与/及` 以最长优先加入拆分连接词，并识别自包含交付物短语，修复「营业执照和税务登记证和组织机构代码证」只产出一个原子导致的假阳性。
- 参数评分从 token 存在性升级为数值比较：注册单位量纲、容差与比较器；无数值候选时才回退子串匹配。
- GET/PATCH `/requirements` 统一走 `judge_for_project()`，与 `/check` 使用同一 deadline 与 matcher；覆盖标注复用 judge 结论，不再漂移。
- 证据按节点携带 `node_id/section_id/heading`；deadline 别名扩展且绝不使用当前时间；表格中 ★/▲/必须/不得 行纳入 requirement 抽取；`ConstraintVerdict.as_dict()` 暴露 source_span/subject/quantity/unit/comparator。

### 3. 评分点驱动生成与上下文管理

- 大台账按段比例截断、行边界裁剪并保留反编造口径块；组装 prompt 按 facts > needs > ledger > outline > digest > KB 贪心分配，受模型上下文预算约束。
- 评分点短语下沉为段级 anchor 与 evidence，未命中则降为 weak/uncovered；`/scoring-coverage` 的 `has_body` 改为按正文真实判定。
- 统一 `is_pending(node)`（空正文 / failed/fallback / 字数不足目标一半）并驱动补写；新增章节遵循度校验（字数比 + bigram 重叠）与流式重试 delta 去重。
- 大纲重建改为 upsert：保留正文、`parent_id` 与 `outline_mode`，返回值按大纲顺序；评分项去重保最大分值并校验总分守恒。可疑数字与知识降级计数写入 `GenerationReport` 与检查 issues。

### 4. DOCX 专业文档引擎与导出集成

- 专业渲染器通过 `export_docx(professional=True)` 正式接入交付链路，支持底版继承、多节/横向、NUMPAGES、奇偶页眉页脚、表格重复表头与核心属性。
- 交付文件导出后执行 DOCX 包完整性校验（error 级阻断）；ZIP 时间戳固定、`as_of` 支持确定性字节；Windows 字体映射、Markdown 超链接、封面/目录/深层级一并补齐。
- 商务标导出读取项目模板并接入一致性门禁：过期/失效报价返回 409，owner 可用 `force/force_reason` 强制并留审计；CLI/MCP 渠道与 API 统一 template 与图片策略。

### 5. 商务标、知识库、Agent 与前端

- 商务标增加包件选择与 `package_id` 透传；企业共享资质/人员/业绩进入商务标与投标前自查；提交后禁止改写；已审批或被引用报价版本禁止删除；审批币种优先使用版本冻结 basis；评估按包件取最差完整率与缺失并集；商务标待审进入跨项目收件箱。
- 企业知识库按 `KbDocument` 生命周期过滤过期/未 ready 文档，真实 PDF 页码/标题来源可追溯；rerank 分数参与排序并暴露给前端；相似度检查改为 queued Job；SQL 预过滤替代全表扫描；KB 删除/迁移级联清理；新增文档列表与预览 API。
- Agent 工作流时间预算改按活跃执行时间计算（审批等待/排队暂停）；上游结果取传递闭包；非法计划返回 400、队列满返回 429；评估 Job 按 job_id 幂等；Finding 跨项目访问 404、状态严格校验、审计写真实 project；新增工作流待审端点。
- 前端：Vite/desktop 代理补齐实际调用命名空间；web 版本对齐 0.29.0；API surface 交叉契约测试；审批类型中文标签、管理控制台滚动条、商务标包件与审批链接分流。

## 已知限制

- 真实招标文件匿名化基线回归仍需项目方提供样本；仓库内只提交聚合基线与文件指纹，不含真实标书内容。
- opt-in 的 PostgreSQL 升级/降级/再升级与备份恢复演练需外部环境（`BIDCRAFT_TEST_PG_URL` / `BIDCRAFT_RESTORE_DRILL=1`），本地默认跳过。
- DOCX/PDF golden 保真测试在缺少 LibreOffice/poppler 的环境跳过；字体替换需部署容器安装 CJK 字体或配置 UNO 替换。
- 远程插件市场自动安装、容器/系统级隔离继续暂缓；质量报告导出与批量评估看板因格式/脱敏口径未定继续暂缓。
- 大模型语义匹配器仍为可选增强，默认规则匹配器为基线；`full/bid` 工作流仍为 `standard` 的带元数据别名。

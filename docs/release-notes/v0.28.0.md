# BidCraft v0.28.0

发版主题：v0.27.0 之后的**能力收口与质量加固**。本版不引入新的业务域，重点是把上一版遗留的判定容错、插件安全、评估联动、异步化与全量分析发现的问题一次性收口。

## 本版内容

### 1. 真实件基线与判定语义容错

- `bidcraft calibrate` 支持 `--label/--note/--manifest/--baseline-index`；新增 `bidcraft baselines` 命令（`--list/--add/--verify`）。
- 基线可附带 `file_manifest`（相对路径 + SHA256 + 大小），`verify_baseline` 核对原始招标文件是否被改动；**只存聚合指标与指纹，不存标书正文**，真实件目录通过 `.gitignore` 排除。
- 基线索引支持按标签/短 id/路径解析，数字签名与指纹核对退出码 0/1/2 可直接用于 CI。
- 实质性条款：同义表述、财务大写数字、`壹级/二级`等等级别名在锚点与约束两层同时兼容，判定证据记录命中方式（`via=synonym`），否定语义仍然生效。
- 约束层同步修复后，改写响应不再被 L3 约束误判为未覆盖；成语/同义词不会凭空生成锚点。

### 2. 插件沙箱、作用域隔离与包签名

- HTTP 插件增加出站地址防护：拒绝本机/私网/元数据 IP 与主机名，检查 DNS 解析结果（防重绑定），保留测试域跳过解析；每次调用前重新校验。可信内网插件需显式 `allow_private_net`。
- 插件新增 `scope=global|owner`、`owner_id`、`allow_private_net`；全局插件对所有调用者可见，个人插件仅归属者与超管可见，本地 MCP 默认只见全局插件。CLI 增加 `--plugin-owner` / `--plugin-all`。
- 插件调用审计记录真实操作者与项目（本地无身份时回退 `system`），并带上 scope/owner 信息。
- `.bidplugin` 支持**可选 Ed25519 签名**：签名写在单个 `manifest.json` 内（`alg/key_id/value`），对规范化 JSON（去签名、排序、无空白）签名。环境变量 `BIDCRAFT_PLUGIN_SIGNING_KEY`（私钥 PEM/路径）、`BIDCRAFT_PLUGIN_TRUSTED_KEYS`（公钥 PEM/Base64/JSON 列表）、`BIDCRAFT_PLUGIN_REQUIRE_SIGNATURE`；导入接口支持 `require_signature=true`。有签名但无信任密钥时 fail-closed，默认仍接受未签名包。包内同时补齐 scope/owner_id/allow_private_net 字段。

### 3. 质量评估异步化与商务完整性联动

- 新增 `POST /projects/{ref}/evaluation/run-async`（202 + Job），前端「后台评估」通过 `watchJob` 展示进度；原同步入口保留兼容。Job 队列新增 `evaluation` 类型与 worker。
- 商务完整性不再是 major 数的代理分：`commercial.validate_commercial_completeness()` 的真实必填项/approved 报价/价格行结果进入评分与报告摘要，未完成会产出 major finding 并影响 verdict；无商务标文档时保持旧行为。
- `submit_commercial` 增加可选 `require_complete` 硬门禁（默认关闭），前端送审弹窗可勾选「严格校验完整性」，命中时在 API 返回 409 并列出缺失项。
- 历史报告切换时按需加载 findings；finding 处置支持意见、处置人展示与重新打开。

### 4. 可选 LLM 语义匹配器

- 新增 `BIDCRAFT_VERDICT_LLM=1` 启用 `verdict_llm.LLMSemanticMatcher`，复用现有 ModelClient 与端点解析。
- 缓存键为（要求、响应、类型），每次核对最多 200 次模型调用；无模型、调用失败、无法解析、预算耗尽时自动回退规则匹配器。
- 约束/结构规则仍然权威：LLM 相似度单独出现**不能**把条款判为 SATISFIED；证据中记录实际 matcher 名称。

### 5. 全量遗留问题修复

按三方分析结论分三类一次性修复：

- **性能/架构**：项目列表 N+1 改为 5 个 GROUP BY 批量统计 + SQL 分页；Job 队列增加状态/复合索引与计数式背压；SSE 支持客户端断连；OCR 解析、PDF/DOCX 渲染、LLM 章节生成移出长事务并补退款；结果构造去重。
- **安全/部署**：补齐管理员用户 CRUD、登录/锁定/登出/改密、支付回调等审计；项目删除保留审计；登录按 IP+全局限流，注册/改密/兑换/各类测试也纳入限流；CSRF 同源检查；生产管理员口令最小长度与占位符拒绝；健康详情按配置收敛；SQLite 多 worker 警告；CI 增加 pip-audit/npm audit/Bandit/Gitleaks 与 Dependabot；日志配置、请求 ID、代理头可信开关；补充备份/恢复与多机 secret.key 说明；安全头加固。
- **产品/文档**：发票开具/驳回前端入口、运行状态面板、复核意见与重新打开、Agent 详情错误恢复与重试、工作流类型约束与审批四眼原则（提交人不得自审，超管可代审）、Web 测试补齐、README/CHANGELOG/路线图/管理指南/evaluation 指南口径与计数更新。

## 已知限制

- 真实招标文件基线校验仍需项目方提供样本并人工确认指标口径；仓库内只提交聚合基线与指纹。
- 远程插件市场自动安装、容器/系统级隔离继续暂缓；当前为应用层沙箱、出站地址防护与作用域隔离。
- 全局运营指标暂无独立聚合端点，管理端「运行状态」展示 `/admin/health` 与指标口径说明；待审批工作台的跨项目工作流待办仅有项目内入口。
- LLM 语义匹配器是可选增强，效果取决于模型配置；默认规则匹配器仍是基线。

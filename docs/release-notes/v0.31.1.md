# v0.31.1 发版说明

**主题：并发可靠性热修复——租约心跳、Reaper 竞争、章节级 fencing 与账务终态**

本版本针对 v0.31.0 上线后仍存在的并发边界进行九阶段热修复。全部改动在独立分支 `fix/v0.31.1-concurrency` 上按阶段提交，保持既有 API 语义，不改历史迁移 0001～0012，不使用 Python 全局锁替代数据库 fencing，不删除或放宽既有测试。

## 1. 生成租约心跳（阶段 1）

- 修复 `pending_charge_heartbeat()` 调用 `touch_generation_lease()` 时缺少 `db` 参数的缺陷；续租改为独立 `session_scope()` 事务，避免长事务污染。
- 新增 `renew_generation_lease(project_id, token)`，状态为 `active|lost|retry|stopped`；确认租约丢失或连续 3 次数据库异常时置 abort 事件，worker 与同步生成入口立即停止。
- 新增 `BIDCRAFT_GENERATION_LEASE_TTL`（默认 1800s，下限 60s）与 `BIDCRAFT_GENERATION_HEARTBEAT_INTERVAL`（默认 60s，自动钳制到 TTL/3 以内）配置项。

## 2. Reaper 租约竞争（阶段 2）

- `_set_failed()` 增加 `lease_expired_before` / `token`，重试上限处的失败迁移与扫描时点保持一致；心跳抢先续租时返回 `lost`，活跃任务不再被误杀。
- 过期生成租约在 `reap_expired()` / `recover_on_startup()` 中统一清理，避免「禁止同项目并发生成」永久卡死。
- 100 轮双 stale 快照竞争与上限唯一失败验证通过。

## 3. 章节级 fencing（阶段 3）

- 新增 `fenced_chapter_write(job_id, node_id, project_id, lease_token)`，在**同一短事务**内校验 Job token 与生成租约，再写 `Section` / `OutlineNode` 与 `done_steps`。
- `generation.writer` 新增 `commit_chapter(info, body, source)` 钩子：异步路径由 worker 提供该钩子，长生成会话不再持有章节写入事务；同步路径行为不变。
- 旧 worker 在章节提交前被回收时抛 `JobAborted`，既不落正文也不记完成账。

## 4. 动态 Worker 矩阵（阶段 4）

- 从 `jobqueue._API_RUNNER_NAMES` 动态发现全部 8 类 runner，逐一验证入口 `raise_if_aborted()`、终态 fencing 写入与预置 abort 下的无副作用行为。
- 为 generation / similarity runner 补上入口中止检查，消除「先写 Job 状态再检查 abort」的竞态。

## 5. 账务竞争（阶段 5）

- 新增取消退款、旧 worker 失败、子账号删除、退款失败可重试四类场景回归。
- `_fail_job()` 对终态幂等：已退款终态直接返回，未退款终态只结算不重复发 `failed` / `refund_failed` 事件。

## 6. 真实件判定一致性（阶段 6）

- 数据集契约支持可选 `responses`（条款→应答文本），`verdict_agreement` 由 `verdict.judge()` 逐条比对期望状态并宏平均；无应答时保持 `null` 并说明原因，不伪造指标。

## 7. 兼容性

- API 路由数量不变；`QualityReport.summary.tender_quality` 新增 `verdict_agreement` 计算能力，前端既有展示无需改版。
- 无新迁移；`0012_generation_lease` 仍为单 head，历史迁移零改动。
- 版本 0.31.1 同步后端、前端与部署清单。

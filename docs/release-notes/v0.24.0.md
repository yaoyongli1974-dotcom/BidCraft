# BidCraft v0.24.0

对标易标专项改造**第一批**：先修三个确定性缺陷，再交付评分覆盖矩阵与 DOCX 专业文档引擎。按四批发布计划，本版只含核心基础能力，不改生成并发模型、不动合同审核机制。

## 一、三个确定性缺陷修复

1. **PDF 导出漏传项目模板**：`POST /projects/{ref}/export` 的 pdf 分支此前未传 `template=`，导致同一项目「导出 DOCX」与「导出 PDF」排版不一致。现已与 docx 分支一致，使用 `export_templates.load(project)`。
2. **`needs` 是死字段**：大纲章节的 `needs`（本章必须引用的事实字段）此前只用于确定性降级正文，AI 生成路径完全看不到。现 `chapter_messages` 增加可选 `needs` 参数并注入 user prompt，生成时逐章传入，向后兼容。
3. **生成时全局知识库被排除**：`_knowledge_provider` 此前把个人库 id 塞进 `kb_ids`，而 `knowledge.search` 在 `kb_ids` 非空时只查这些库——注释声称「全局库仍可用」但实际被排除。现给 `search` 增加追加语义的 `extra_kb_ids` 参数（不改变 `kb_ids` 既有的排他语义），生成侧改为全局库 + 个人库联合检索。

## 二、评分覆盖矩阵（只读）

- 新增 `GET /projects/{ref}/scoring-coverage`：逐条评分点列出其匹配的章节与覆盖状态（covered / weak / uncovered），汇总已覆盖分值、覆盖比例与未覆盖提示。
- 匹配口径保守：section_hint 全等 > category 命中 > 标题相似度（与评分大纲对称）；有正文且 ≥120 字才算 covered，短正文记 weak 且不计入已覆盖分值。
- 支持一对多、多对一；**纯只读**，不写库、不改大纲、不触发生成，viewer 可读。
- 前端 `OutlineTab` 增加评分覆盖区块（`ScoreCoverage` 组件），展示分值覆盖进度、未覆盖提示与逐条章节对应。

## 三、DOCX 专业文档引擎（新增模块，不替换现有导出）

新增 `bidcraft/documents/`：
- **Document IR**：统一文档中间表示（节 / 段落 / 表格 / 样式 / 页面设置 / 页眉页脚 / 核心属性），支持从章节 Markdown 构造。
- **模板解析**：读取既有 DOCX 的字体（含 eastAsia）、页面尺寸/页边距、页眉页脚，损坏文件返回明确错误而非静默丢弃。
- **渲染器**：支持 Word 模板继承、分节与横向页、多级标题、东亚字体、首页/奇偶页不同页眉页脚、PAGE/NUMPAGES 域、表格重复表头与防跨页拆分、列宽与题注、占位符原样保留。
- **导出后校验**：标题跳级、空白页迹象、表格表头、图片引用、占位符清单、核心属性，输出可审阅报告。

现有 `export_docx()` 调用签名与行为保持不变；本版 DOCX 引擎为独立能力，供后续导出集成使用。

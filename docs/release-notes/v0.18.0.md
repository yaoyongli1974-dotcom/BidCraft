# BidCraft v0.18.0

实质性条款的自动判定从「模式是否出现」升级为「约束是否成立」。这一版修掉三个会被用户直接看出来的误判：数值更小却算满足、语义相反却算满足、复合条款只响应一部分却算整条覆盖。

## 本版内容

### 1. 数值与等级比较（约束方向）

过去锚点只检查「条款和正文是否都出现了数字与单位」，于是「不小于 1000 Mbps」遇到正文「500 Mbps」仍算命中。现在抽出可比较约束，按方向判断：

- **至少 / 不小于 / 不少于 / ≥**：正文值必须 **≥** 要求值（带宽 1000、业绩 3 项、注册资本 1000 万）；
- **至多 / 不大于 / ≤ / N 小时内响应**：正文值必须 **≤** 要求值（响应时间越短越好）；
- **质保 N 年**：正文值必须 **≥** N 年，且「5 年」与「60 个月」按同一量纲比较；
- **资质等级**：一级 ≥ 二级、特级 ≥ 一级，按等级序比较（甲级 / 乙级是另一量纲，不与一级混比）。

中文数字（「六项」「近三年」）与阿拉伯数字都识别。数值提取按**同量纲**挑选，避免拿「近三年」的「三」去应答「不少于 3 项业绩」。「近 N 年」是描述性时间窗，保持既有口径——不当成 <= N 年的硬约束。

### 2. 否定语义

两种字面命中都不再算覆盖：

- **整句包含**：「我方不具备一级建造师资格」包含「具备一级建造师资格」，但先查否定词，命中落在否定句里直接判不满足；
- **锚点命中**：否定句里的「一级建造师」锚点也不计入覆盖率。

否定只在**同一子句**内生效（逗号、句号、分号切分），不会跨句误伤——「我方具备一级建造师资格。其他资质暂不具备。」仍然判覆盖。比较级表达里的「不」（不低于 / 不小于 / 不超过）不算否定词。

### 3. 复合条款拆成多条约束

一条条款含多个独立要求时（例如「一级资质 + 近三年不少于 3 项业绩 + 2 小时内响应」），现在拆成多条约束**逐条比较**：全部满足才算整条覆盖，少一条、或某条数值更差、或某条被否定，都会判未响应。约束可以分散在不同章节响应。

判定结果以 `constraint` 数组写进核对问题的 `evidence`，逐条给出 `label / state / detail`（state 为 satisfied / violated / absent），让「哪条没过」直接可见、可举证。问题的 message 也会标注「数值/等级/否定语义不符合」或「部分约束未在正文体现」。

## 说明

- 仍是**规则比较**，不是 LLM 语义判定：同一份正文每次结果一致，判定可复核、可举证。
- 主体关联靠词族（业绩 / 资质 / 响应 / 质保 / 带宽），正文数值必须与条款讲的是同一件事才算数。「42 个机柜」不会误当作业绩数量。
- 开放域语义等价（公司名、产品型号别名等）仍不做；这部分继续靠 3-gram / 锚点基线和人工确认。
- 人工标记「已响应 / 不适用」的条款不受影响，自动判定只作用于 pending 条款。

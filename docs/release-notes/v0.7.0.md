# BidCraft v0.7.0

实质性条款不再靠人翻。评分办法里标了 ★/▲ 的条款，现在会在核对时逐条对照正文——
没写就是阻断项，直接拦在导出前。

## 本版内容

### 1. 解析：保留标记与原文

- `★` / `▲` 不再被折叠成一个 `mandatory` 布尔：`Requirement` 新增 `marker` 字段，
  原文符号与原文行都保留（此前 `source_quote` 存的是章节标题，指不到具体条款）。
- 条款扫描的章节门控补上 **评标 / 评审 / 评分**：实质性要求大量写在「第三章 评标办法」里，
  以前这一章根本不会被扫描。

### 2. 响应判定（`bidcraft/substantive.py`）

- 对每个实质性条款（有 ★/▲ 标记，或解析期判为 mandatory），用**字符 3-gram 覆盖率**判断
  正文是否正面回应：核心短语的 3-gram 有 45% 以上出现在某一章，才算「该章已覆盖」；
  短条款要求整句命中。中文没有词边界，逐字比较会把「改写过但意思到了」的响应误判成未响应。
- 判定刻意**保守**：拿不准就报出来（fail-closed），人工再确认。不做 LLM 逐条判定——
  条款响应要能复核、能举证，同一份正文每次结果必须一致。
- 未响应 → 生成核对问题：**★/▲ 判 `blocking`（最高优先级，进导出门禁）**，
  仅「必须/不得」的判 `critical`。编号 `SUB-001…` 按「★ → ▲ → 普通」的稳定顺序分配，
  确认某一条不会让其它条编号漂移。
- 已被正文覆盖的条款会回填 `section_id` / `node_id` / `auto_covered`，总览页可直接跳到该章。

### 3. 人工确认（留痕）

- 条款状态：`pending`（待确认）/ `responded`（已响应）/ `na`（不适用）。
- **标记「不适用」必须填写原因（≥4 字）**，记录操作人与北京时间；可撤销回到待确认。
- 已确认的条款不再产出核对问题，也不计入导出阻断。

### 4. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/projects/{ref}/requirements` | 条款列表 + 响应状态 + 覆盖章节（viewer 可读） |
| PATCH | `/projects/{ref}/requirements/{id}` | `{response_status: responded\|na\|pending, note?}` |

- 新增列：`marker`、`response_status`、`response_note`、`responded_by`、`responded_at`、
  `section_id`、`node_id`、`auto_covered`；幂等 additive 迁移，老库直接启动。
- 审计 action `requirement.response`。

### 5. 前端：风险总览页新增「实质性条款响应」

- 摘要显示「共 N 条 · 未响应 M · 正文已覆盖 X · 已响应 Y · 不适用 Z」；有 ★ 未响应时
  顶部直接提示「导出会被拦截」。
- 状态筛选：未响应 / 正文已覆盖 / 已响应 / 不适用 / 全部（默认只看未响应）。
- 每条显示标记、条款原文（可展开）、招标原文、覆盖章节跳转；可标记已响应 / 不适用（填原因）/ 撤销确认。
- 只读成员可查看与跳转，不能确认。

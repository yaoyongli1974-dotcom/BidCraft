# BidCraft v0.8.0

一次纯架构重构：把 god object 拆开，同时把「配置错了要跑半天才知道」和「HTTP 层自己做耗时任务」两个老问题收掉。**所有 URL、请求/响应格式、业务函数签名、数据库结构都没有变化**——升级不需要改前端、不需要改脚本、不需要迁移数据。

## 1. API 分层（原 `api.py` 275 KB / 6702 行）

- `bidcraft/api/app.py`：应用装配、共享 helper、模型定义，**1929 行**。
- `bidcraft/api/routes/`：按业务域拆出 12 个路由模块，合计 **194 个路由**，与重构前逐一对应（OpenAPI 144 paths / 194 operations）：
  `auth` / `account` / `billing` / `admin` / `projects` / `my` / `jobs` / `batch_jobs` / `legal` / `packages` / `health` / `approvals`。
- `bidcraft/api/__init__.py` 做模块别名，让 `from bidcraft.api import create_app` 等既有导入路径继续可用；路由模块在 `create_app()` 内延迟导入，避免循环依赖。
- 原单文件中被路由闭包捕获的 39 个 helper / 模型提升到模块级；`auth_guard` / `security_headers` / `not_found` 因引用 `app` 仍留在 `app.py`。
- 特别处理了两个隐藏耦合：SPA 静态目录路径按新文件位置改成 `.parent.parent`；`admin_health` 通过模块别名取 `app.state`，SSE/middleware 行为不变。

## 2. 后台任务从接口层剥离

- 5 个 `_run_*_job()` 搬到 `bidcraft/workers/`（generation / images / compliance / knowledge / export）。
- 8 个跨任务共享 helper 与 3 个常量搬到 `bidcraft/services/job_support.py`。
- 依赖方向单向：`api → workers / services`，workers 不反向引用 API。`bidcraft.api` 仍显式 re-export 这些名字，测试里 `monkeypatch.setattr(bidcraft.api, "_run_kb_reindex_job", ...)` 照常生效。
- 换任务队列时只替换 worker 层，HTTP 路由不用动。

## 3. 配置启动校验与环境区分

- `bidcraft/config.py` 新增 `env`（dev / test / prod，默认 dev）：
  - **dev / test**：缺模型、支付、超管密码等参数只告警，方便本机起服务；
  - **prod**：启动时缺关键参数直接 `RuntimeError`，不再等到用户点支付/生成才报错。
- `validate_startup()` 是纯函数，不发网络请求；`safe_dict()` 输出脱敏视图（密钥只留尾 4 位），日志与审计不再漏明文。
- 密钥轮换与备份：环境变量集中配置，轮换时改环境变量并重启服务；旧密钥的备份由部署方在自身密钥管理系统中保留，程序不落盘明文。

## 兼容性与验证

- 路由 URL、HTTP 方法、状态码、响应体、请求模型、业务函数签名全部不变；老库无需迁移。
- 后端：**788 passed**（新增 `tests/test_worker_extraction.py` 8 例、`tests/test_api_package.py` 4 例），ruff 全绿。
- 前端：lint 0 errors / 0 warnings，169 tests，build exit 0（本版未改前端逻辑）。
- 守护测试：workers/services 不得 import API；`bidcraft.api` 的 re-export 与实现是同一对象（保证 monkeypatch 语义）；路由模块不得出现越级相对导入；shim 指向正确的 app 模块。

# BidCraft v0.12.1

纯前端架构重构：**页面不再直接依赖巨型 api 模块**，任务进度、错误处理、权限判断、并发冲突各自收口到一处。无服务端改动、无行为变化；SSE 实时流 + 断线轮询兜底的能力完整保留。

## 本版内容

### 1. API 请求与业务页面分离
- 原 `web/src/lib/api.ts`（4,275 行 / 238 导出）按域拆成 `web/src/api/` 下 14 个模块：
  `auth / project / tender / ledger / generation / compliance / boq / knowledge / billing / jobs / images / plugins / account / shared`。
- 传输层（请求桥、`ApiError`、`messageOf`、上传、桌面桥、401 事件）独立为 `web/src/lib/http.ts`。
- 全站 61 处 import 改为 **直接指向具体域模块**，旧 barrel 删除；不引入 Redux，不改页面结构。

### 2. 统一任务状态管理（保留 SSE 断线恢复）
- 新增 `web/src/hooks/watchJob.ts`：全站唯一的任务观察器，封装 SSE 事件流、轮询兜底、
  终态只结算一次、连续失败计数、断线自动降级。
- 全书生成、配图批次、知识库重建三处各自重复的 `EventSource`/`setInterval`/重连逻辑
  全部改为调用 `watchJob`；各页面只保留「拿到进度后做什么」的回调。
- 刷新/切页后重新挂载任务、断线回退轮询、token 级预览等既有能力不变。

### 3. 统一错误处理
- `ApiError` / `errorDetailText` / `messageOf` / `chapterConflict` 全部集中在 `lib/http.ts`，
  校验数组、缺项提示、409 冲突 payload 的解析口径全站一致。

### 4. 统一权限能力判断
- 新增 `web/src/lib/permissions.ts`：把散落在页面的 owner/admin/viewer 判断收敛成
  `canGlobalWrite / isProjectAdmin / canEditProject / canReviewChapter / canForceWrite / canManageProject`。
- 老后端省略 `my_role` 的兼容行为由函数参数显式表达，不再各处隐式重复。
- AuthContext、草稿复核、导出强制、协作成员、清单审批、项目删除/复制、工作区只读
  七处改为调用统一能力函数。

### 5. 章节并发编辑冲突提示
- 现有冲突链路确认可用：保存 409 → `chapterConflict` 解析乐观锁字段 → 弹窗展示服务器版本
  （修订号/字数/正文预览）→「载入最新 / 强制覆盖」两条明确路径；再次冲突会重新提示，
  不会产生静默覆盖。本版为该解析逻辑补齐回归测试。

## 说明

- 没有引入状态管理库，也没有为了目录结构调整任何业务页面。
- `api/*.ts` 的拆分是机械拆分，函数签名、返回结构、字段名与旧 `api.ts` 完全一致。

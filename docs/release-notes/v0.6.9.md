# BidCraft v0.6.9

交付前风险总览 + 导出硬门禁。核对此前只是「一份问题清单」，现在它是一道能拦住交付的门。

## 本版内容

### 1. 风险总览页（`/app/projects/<ref>/risk`）

- 按 **废标/阻断、严重、主要、提示**四档聚合全部核对问题（`minor` 与 `info` 合并进「提示」档，
  条目保留原始等级）；每档显示未处置/总数/已处置，阻断档有未处置项时高亮脉动。
- 顶部结论横幅直接给交付判断（阻断 / 需关注 / 通过）、上次核对时间与各档计数。
- **章节锚定**：`check` 现在把问题锚定到大纲节点（`node_id`/`section_id`/`heading`/`position`）。
  定位规则是 heading 精确匹配优先、其次包含匹配，多 heading 取第一个可匹配项；匹配不到就留空，
  不猜。卡片上的位置可点击，跳转正文后自动选中该章并按证据引文在渲染结果里查找段落、
  平滑滚动并临时高亮；找不到段落时退化为「已定位到章节」提示。
- **状态流转**：标记已处理、忽略（必填原因）、恢复待处理；只读成员可查看与跳转但不能处置。
  支持按当前筛选批量标记已处理。
- **处置状态跨核对保留**：重新核对时按 `(code, location, finding)` 快照旧状态，`finding` 未变则沿用
  处置结果，变了才重开——不会因为你改了一处正文就把其余已处置项全部打回。

### 2. 导出硬门禁

- 存在**未处置的阻断项**时，`POST /projects/{ref}/export` 对 docx / pdf / md / markdown 返回
  **409**（detail 为可读原因）；**xlsx 台账导出不受限**。
- 防止门禁被绕过：HTTP、MCP 工具、CLI（`bidcraft export` 与 `bidcraft run` 末尾导出）、后台批量导出
  四条路径使用同一套判定（`bidcraft/export_gate.py`），批量导出逐项目拦截、被拦项目记入 `failed`
  且其余继续、不提供 force。
- **强制导出**：仅 owner/admin 可填原因（去空白 ≥4 字）强制导出，写 `export.force` 审计；
  editor 调用 force 返回 403，原因过短返回 400。

### 3. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/projects/{ref}/risk-overview` | 四档聚合 + verdict + gate + 分类统计 + 明细（viewer 可读） |
| PATCH | `/projects/{ref}/issues/{id}` | `{status: open\|handled\|ignored, note?}`；忽略必填原因 |
| POST | `/projects/{ref}/issues/bulk-status` | `{ids: ≤200, status, note?}` |
| POST | `/projects/{ref}/export` | 新增 `force` / `force_reason` |

- 新增字段：`node_id`、`section_id`、`heading`、`position`、`checked_at`、`resolved_at`、
  `resolved_by`、`resolution_note`；`status` 统一为 `open` / `handled` / `ignored`
  （读取侧兼容历史的 `resolved` / `closed`）。
- 库内时间统一存 naive UTC，出站一律序列化为 `+08:00`（`clock.utc_now()` / `clock.iso_beijing()`）。
- 迁移为幂等 additive（`db._migrate_columns`），老库直接启动即可。

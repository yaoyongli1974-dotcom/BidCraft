# BidCraft v0.27.0

对标易标专项第四批（收官）：**投标质量评估中心**。把散落在规则引擎、★/▲ 判定、来源追溯、评分覆盖、章节确认、导出门禁中的结果**聚合**成一份可审计的质量报告——不重复实现任何合规/判定规则，只读现有权威组件。

## 本版内容

- **六维质量评分**：资格符合性 20% / 实质性响应 25% / 评分点覆盖 20% / 技术内容质量 15% / 商务完整性 10% / 文档交付质量 10%，权重可配置（不写死在多处）。综合分 + A/B/C/D 等级 + pass/warn/blocked 结论。
- **硬性风险一票否决**：★ 实质性条款未确认、未处置 blocking 风险 → verdict 强制 blocked；**综合分不抵消废标风险**，质量分不称为中标概率或实际评标得分；证据不足的维度不自动给高分。
- **四类覆盖聚合**：实质性条款四态、评分点覆盖（复用 `generation.coverage`）、证据/来源追溯 stale（复用 `provenance.report`）、章节确认（复用 `export_gate.unconfirmed_chapters`）。
- **风险聚合**：读取现有 Issue / ★条款 / 导出门禁状态，产出四档计数、硬风险清单、处置建议；人工处置状态被保留（不因聚合而清空）。
- **不可变报告快照**：每次运行 `report_version = max+1`，历史报告与 finding 原文不被后续核对覆盖；finding 的处置状态单独更新并写审计（含处置人/意见）。
- **API**：`POST /projects/{ref}/evaluation/run`（写权限）、`GET /projects/{ref}/evaluation`（最新）、`GET /evaluation/reports`、`GET /evaluation/reports/{id}`、`GET /evaluation/reports/{id}/findings`、`PATCH /evaluation/findings/{id}`。
- **前端**：新增「质量评估」tab 与 `web/src/api/evaluation.ts`：综合分/等级/结论概览、六维进度条、硬性风险横幅、处置建议、问题清单与人工处置、历史报告切换。运行评估受写权限控制（viewer 禁用）。

## 数据库变更

新增 Alembic `0007_yibiao_batch4`（down=`0006_yibiao_batch3`），两张表：`quality_reports`（报告快照）、`quality_findings`（问题项）。幂等 upgrade；downgrade 先删索引再删表；upgrade/downgrade/re-upgrade 实测全通。无既有表结构改写。

## 兼容性

- 无对外 API 结构变化（只新增 `/evaluation` 系列端点）。
- SQLite / PostgreSQL 双后端通用（新表 nullable 默认值 + 幂等 create_table）。
- 质量评估只读现有业务数据，不修改招标文件、正文、报价与确认状态。

## 已知限制

- 质量分是内部参考分，不是评标得分；★ 硬风险不看分数。
- 评估为同步生成报告快照（非 Job Queue 长任务），大体量项目后续可迁 runner。
- 商务完整性维度暂以核对结果 major 数反向衡量，未接入独立商务标评估（商务标在 v0.25.0 已有 completeness 校验，可在后续版本联动）。

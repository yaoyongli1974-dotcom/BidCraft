# BidCraft v0.19.0

实质性条款判定从「模式匹配 + 二值覆盖」升级为**五层可解释判定引擎**。核心变化是引入
四态结论（满足 / 不满足 / 部分满足 / 人工复核）与逐层证据留痕，并把「语义相似不代表
实质性要求满足」写进结构：数值、等级、时间、否定的判定始终由确定性规则负责，语义层
可插拔但推翻不了硬约束。

## 五层结构

1. **招标条款提取**：保留原文、`source_quote`、**页码**、**条款编号**、★/▲ 标记
   （`RequirementItem` / `Requirement` 新增 `page` / `clause_no`，老库自动补列）。
2. **原子约束拆分**：一条复合条款按子句拆成独立可验证的原子要求（`split_atoms`）。
3. **结构化约束提取**：对象、数值、单位、等级、时间窗、数量、比较关系、否定条件
   ——复用 `constraint_check` 的确定性规则，时间窗作为**证据维度**提取。
4. **多维响应验证**：语义（3-gram + 锚点，**可插拔 `SemanticMatcher`**）、数值 / 等级 /
   否定 / 主体关联（规则引擎）、时间范围（证据）。默认 `RuleSemanticMatcher` 确定性、可复现。
5. **判定与证据留痕**：四态结论 + 每层证据写入 issue.evidence 与 `GET /requirements` 响应。

## 四态判定与门禁（按确认的策略）

| 判定 | 含义 | 门禁 |
|---|---|---|
| 满足 satisfied | 全部硬性约束满足、证据充分 | 放行 |
| 不满足 unsatisfied | 任一硬性约束不满足（如 1000Mbps vs 500Mbps、二级资质 vs 一级、否定语义） | 阻塞（★=blocking，其余=critical） |
| 部分满足 partial | 复合条款部分约束已证实、部分缺失 | 阻塞（同上） |
| 人工复核 review | 语义相近但证据不足 / 时间范围偏短 | **info，可见但不阻塞导出** |

判定优先级：**约束否决先于语义相似**——一条正文就算语义上再像，只要数值/等级/否定
不符合，就判不满足。语义 matcher 给满分也推翻不了这条（有 `PerfectMatcher` 测试守着）。

## 时间窗口径（守住既有正确判定）

「近 N 年」**不升级成 <= N 的硬比较**：「近五年 6 项」覆盖「近三年不少于 3 项」仍是既有
正确口径。时间窗只作为 L3/L4 证据；正文时间范围短于要求时记一条 review 信号（转人工复核），
绝不判 violated，也不改变既有 `constraint_blocked` 判定。

## AI 语义接口（预留，不接 LLM）

`SemanticMatcher` 协议允许将来注入基于模型的语义实现替换默认规则层，但数值 / 等级 /
时间 / 否定始终由 `constraint_check` 的确定性规则负责——「语义相似不代表满足」由结构保证，
不靠提示词。本版不引入任何 LLM 依赖，判定完全可复现、可举证。

## 接口变化

`GET /projects/{ref}/requirements` 每条新增：`page`、`clause_no`、`verdict`、
`verdict_label`、`verdict_reason`、`verdict_level`、`verdict_layers`（五层证据）。
前端实质性条款清单显示四态徽章、判定说明与招标定位（页码/条款号）。旧后端缺字段前端按
undefined 兼容处理。

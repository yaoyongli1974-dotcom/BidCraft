# BidCraft v0.26.0（对标易标第三批）

本版完成 Agent 编排系统与项目协作/版本管理，均基于现有基础设施增量扩展：任务队列、fencing、幂等账本、SSE、权限、审计、章节复核状态机全部复用，没有另起一套。

## 本版内容

### AI Agent 编排
- **Agent 注册表**：统一 `BaseAgent` 接口（validate_input/build_context/execute/validate_output），6 类 Agent（招标解析/规划/技术标/商务标/知识/合规/复核），统一输出结构；Agent 不直接写库，只通过受控 Service 调用。
- **DAG 工作流**：`build_workflow/build_task_dependencies/validate_workflow_graph`，任务依赖可并行（企业资料匹配与清单分析），检环与孤立节点。
- **编排器**：`start_workflow/dispatch/retry/cancel/resume`，工作流状态与 `WorkflowRun/WorkflowTask` 同步；任务按 run_id+task_key 幂等；失败可单独重试；预算熔断；Agent 输出经 Pydantic 校验；失败不伪装成功。
- **人工审批闸门**：`request_approval/approve/reject/resume_after_approval`，六类审批（技术/商务/企业资料/报价/合规风险/最终交付），复用项目成员权限 + 审计；无权限不能审批，审批前不执行受控后续任务。
- **模型工具调用**：`ModelClient.complete_with_tools` 解析 `tool_calls`/`finish_reason`（OpenAI 兼容），原 `complete()` 签名保持不变；工具层薄包装 MCP 内置工具与插件工具，复用沙箱/allowlist/审计。
- **审批不占 Job 租约**：`waiting_approval` 是独立工作流状态，审批挂起时 Job 正常结束，审批后由路由重新调度——避免与 reaper 租约语义冲突。

### 项目协作与版本管理
- **章节编辑锁**：`lock_token` + 有效期，原子获取（SQLite/PG 一致），锁拥有者才能续期/释放；编辑锁与审核锁（`review_status=locked` 终态冻结）分离；viewer 不能获取；过期锁可自动回收。
- **修订历史**：每次有效正文保存生成 `SectionRevision`（revision 与 `Section.revision` 对齐，sha256 body_hash，保存人/时间/原因）；支持版本列表、双版本 diff、历史恢复；恢复生成新版本不覆盖历史；已确认章节恢复前须按现有复核机制撤回。
- **保存钩子**：`save_chapter` 在正文写入的同一事务内调用 `snapshot_on_save`，失败整体回滚。
- **章节分工**：`ChapterAssignment`（负责人/协作/截止/状态），指派人须为项目成员，全程审计。

### 数据与兼容
- 新增 Alembic `0006_yibiao_batch3`：6 张表（workflow_runs/tasks/approvals、section_revisions/edit_locks、chapter_assignments），幂等 upgrade + downgrade（先删索引再删表），实测 upgrade→downgrade→re-upgrade 全通。
- 无对外 API 结构变化，只新增端点；章节确认继续用现有 `review_chapter`，未另建状态机。
- 前端新增 Agent 编排 tab、章节修订/恢复入口、章节分工区块；路由与骨架同步（14 个 tab）。
